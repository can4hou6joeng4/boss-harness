## 当前候选与客户端升级

当前源码使用 npm `0.2.0-rc.771` / Python `0.2.0rc771` 与 JSON-RPC `0.2.0`；`main` 为开发分支，最新实际预发布见 [GitHub Releases](https://github.com/can4hou6joeng4/boss-harness/releases)。下列客户端约束保持兼容；逐批变更、修复计数与候选准备历史见 [CHANGELOG](../CHANGELOG.md)，不从使用指南重复发布状态。

- 握手的 `protocolVersion` 使用字符串，`capabilities` 使用对象或 null。非法类型返回 `-32602`，同一连接可修正参数后重试握手。
- `thread/read` 和 `thread/resume` 的 `snapshot` 使用布尔 true / false，不能用字符串或 null。true 返回冻结快照，缺省或 false 返回普通读取。
- `turn/interrupt` 只有省略 `turnId` 才表示停止当前回合；显式目标必须是非空、非纯空白、最多 128 字符的字符串。非法值在设置取消信号前返回 `-32602`，不会悄悄停止其他目标；有效旧目标仍以 `-32004` 拒绝。
- `queue/add` 的 `autoCompaction` 应省略或使用合法部分覆盖对象，空对象 `{}` 可用，null 不可用。已有请求重试也先校验，非法值不改动原队列项；同一请求编号的不同合法覆盖仍返回冲突。
- `context/compact/start` 的 `model` 只有省略才继承摘要配置；显式值须为最多 200 字符的非空模型 ID，不含空白。空串、空白、数字、布尔、数组、对象、null 与超长值在创建任务前返回 `-32602`，不会静默改用默认模型。
- `thread/start` 的 `projectId` 与 `thread/list` 的 `projectId` 筛选须为最多 200 字符的字符串；超长值返回 `-32602`，会话文件不会写入。旧版本留下的超长标识在读取投影中截断为前 200 字符并带 `projectIdTruncated: true`，原始会话头不改写，这类会话可重新读取。
- 会话标题（`thread/start.title`、`thread/name/set.name` 与 `thread/fork.title`）须为最多 500 字符的字符串；超长值返回 `-32602`，不会写入会话文件。旧版本通过 `thread/fork` 留下的超长标题在读取投影中截断为前 500 字符并带 `titleTruncated: true`，原始会话头不改写，这类会话可重新读取。
- 从上述历史会话创建新分支时，分支不保存来源读取投影的 `titleTruncated` / `projectIdTruncated` 标记；来源项目标识已截断时不继承 `projectId`，避免按不完整标识分组。普通会话仍完整继承标题与项目标识；此修正作用于新建分支，已有文件不追溯改写。
- `context/edit/read` 与编辑成功回执受约 1 MiB 单页响应预算约束，按完整投影编码后的大小计算。超限返回 `-32010` 且本次编辑不写入、不发送编辑通知；传输中断后的提交仍须回读核对。分页可核对长助手原文，但不会绕过该预算，限制与替代做法见[消息的后续模型上下文](#消息的后续模型上下文)。
- 桌面编辑后续上下文被内核明确拒绝时，显示「未受理、没有写入」与错误码；回执未确认仍保留待核对说明，不自动重试。
- 分支切换途中断连后，旧队列核对回执不会继续提交，旧切换回执不会关闭重新打开的窗口或覆盖新操作状态。恢复连接后先核对当前位置，再按需确认；已生效的切换不回滚。
- 分支摘要取消回执只更新发起时连接中的同一任务：重连或任务更换后，旧成功、失败与收尾不会提前解锁当前取消、覆盖其进度提示或写入旧连接的失败说明；新任务不继承旧任务的取消等待。取消受理后仍以任务终态为准，回执任务编号不符时提示核对，不自动重发。
- `attachment/read` 省略 `cursor`、`limit` 与 `sha256` 时整份返回附件正文；整份回执超过约 1 MiB 单页预算时返回 `RESPONSE_TOO_LARGE`，错误数据给出 `recoveryMethod=attachment/read`、总字符数与建议分段，客户端应改用分段读取。分段回执为 `text`、`offset`、`nextCursor` 与绑定附件摘要的 `contentRef`；续读时回传 `contentRef.sha256`，附件被替换后返回 `STALE_ATTACHMENT`。未知参数、非法游标与越界 `limit` 返回 `-32602`。提示词中的附件名称按 JSON 字符串字面量转义，文件名含换行或控制字符时不会伪造出额外的附件标注行。

协议与内核仍为 `0.2.0`，没有数据迁移或新增工具权限。完整字段与返回码见[内核与业务契约参考](TECHNICAL_REFERENCE.md)。

## 模型配置来源

OpenAI Responses 的完整显式配置由以下三项组成，去除首尾空白后均须非空：

| 配置 | 来源 |
| --- | --- |
| 端点 | `BOSS_HARNESS_OPENAI_BASE_URL` |
| 凭据 | `BOSS_HARNESS_OPENAI_API_KEY` |
| 模型 | 命令行 `--model`，其次为 `BOSS_HARNESS_MODEL`、`BOSS_HARNESS_OPENAI_MODEL` |

三项齐备时不访问 Codex 配置文件，Python 3.10 也可使用这一路线；可选推理强度只取 `BOSS_HARNESS_EFFORT`，未指定则由模型服务决定，不再继承文件中的值。`BOSS_HARNESS_MODEL` 覆盖进程默认 provider 的模型；`BOSS_HARNESS_OPENAI_MODEL` 可为 OpenAI 线路提供模型，Anthropic 线路对应 `BOSS_HARNESS_ANTHROPIC_MODEL`。`--model` 和模型变量为空或只有空白时视为未设置，继续按顺序取下一项。`BOSS_HARNESS_PROVIDER=auto` 与省略该变量等价，字母大小写与首尾空白不影响判定；其他拼错的值仍以 `MODEL_PROVIDER_UNKNOWN` 失败。自动线路判断同样只认去除首尾空白后非空的 `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN`：两项均为空或只有空白时按未配置处理并回退 `none`，与自检的凭据规则一致。启动 Anthropic 线路时，凭据也先去除首尾空白再交给 SDK；`ANTHROPIC_API_KEY` 只有空白时不会遮蔽真实可用的 `ANTHROPIC_AUTH_TOKEN`。模型目录发现与摘要线路解析同样沿用这条规则：两项凭据都只有空白时，目录不列出 anthropic 线路，摘要请求直接以 `COMPACTION_MODEL_UNAVAILABLE` 拒绝，而不是等构造供应商时才失败。显式端点写成 `http://` 且主机不是 `localhost`、`127.*` 或 `::1` 时，自检的模型检查会警告 `MODEL_ENDPOINT_INSECURE`，提示凭据可能以明文传输；自检不输出端点，也不会发起请求。显式推理强度不属于 `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max` 时，自检警告 `MODEL_EFFORT_UNSUPPORTED`，说明模型请求可能失败；若 `BOSS_HARNESS_MODEL_LIMITS` 为该模型声明了非空 `reasoningEfforts`，而显式强度不在其中，同样警告该码并提示与容量声明不符。Anthropic 线路下 `BOSS_HARNESS_THINKING` 仅识别 `summarized`，其他非空取值被忽略时自检警告 `MODEL_THINKING_IGNORED`，OpenAI 与 none 线路不受该开关影响。

Anthropic 线路另有三个可选项。`BOSS_HARNESS_SERVER_FALLBACK` 控制请求是否携带服务端回退参数（走对应的 beta 接口）：未设置时，`ANTHROPIC_BASE_URL` 未设置或指向官方主机则开启，指向其他网关则关闭；显式取值去除首尾空白并按不区分大小写解析，`1` / `true` / `yes` / `on` 为开启，`0` / `false` / `no` / `off` 与空值为关闭，其他取值以 `MODEL_SERVER_FALLBACK_INVALID` 明确失败，不会被当作开启。网关不支持该参数时应保持关闭。`BOSS_HARNESS_THINKING=summarized` 请求模型返回思考摘要，其他取值或未设置时不请求。`BOSS_HARNESS_PROMPT_CACHE` 控制回合请求是否携带提示缓存断点：默认开启，不随端点变化；开启时内核在系统提示与最后一条用户消息（工具回合为最后一个工具结果）上各设置一处 `cache_control` 断点，不指定保留时间，也不改变模型可见内容，摘要任务与连接检查的请求不带断点。取值同样去除首尾空白并按不区分大小写解析，`0` / `false` / `no` / `off` 为关闭，`1` / `true` / `yes` / `on`、空值与未设置为开启，其他取值以 `MODEL_PROMPT_CACHE_INVALID` 明确失败，不会被当作开启或关闭。所用网关拒绝 `cache_control` 字段时应设为关闭。是否命中由模型服务决定：提示过短，或模型、网关不支持时，请求照常完成但不产生缓存；服务端上报的结果可在「会话用量」的缓存读取与缓存写入中查看。这三项只作用于 Anthropic 线路，`none` 与 OpenAI 线路不因它们失败。

选择 `none` 时（显式 `--provider none`、`BOSS_HARNESS_PROVIDER=none` 或没有可用凭据时自动回退），内核不读取模型名与推理档位：握手、`config/read`、`model/list` 与新建会话统一使用 `none · none`，设置 `BOSS_HARNESS_MODEL` 或 `BOSS_HARNESS_EFFORT` 不会改变该线路，也不会发起模型请求。`none` 仍可调用招聘 CLI 与上游只读工具。桌面「设置 → 模型与连接」的「模型服务」卡片把这条默认线路标为「未启用」，并注明招聘 CLI 仍可运行、可能访问平台；它不表示离线。

显式指定 `none` 与自动回退为 `none` 的含义不同。显式指定（`--provider none`，或未传 `--provider` 时 `BOSS_HARNESS_PROVIDER=none`）是进程级开关：整个进程不构造模型传输，`model/list` 只会列出 `none · none`，不能在会话里改选其他线路；记录在真实线路上的旧会话在本进程内读上下文、发回合、续接或添加新的排队消息都会被拒绝并说明原因，切到 `none` 线路后仍可使用只读指令，摘要线路（含另配的 `BOSS_HARNESS_COMPACTION` 摘要 provider）同样不可用，`summaryAvailable` 为 `false`。需要模型时改用具体 provider 重新启动，旧会话在对应线路进程内保持可用。自动回退只是没有默认线路：没有可用凭据时进程默认落在 `none · none`，环境中另已配置的线路仍会出现在 `model/list`，可在会话里选用。桌面只经环境变量传线路，因此桌面启动要以具体 provider 运行才能获得其他可选线路；`BOSS_HARNESS_PROVIDER` 为空或只有空白时桌面按默认 `openai` 线路启动，与其他空白取值规则一致。握手与 `config/read` 都返回 `modelCallsDisabled` 字段：显式指定时为 `true`，自动回退与真实默认线路为 `false`。桌面模型菜单在 `none · none` 选项之后说明显式禁用及恢复方式，「运行状态」概览的「模型调用」也会显示进程级状态。菜单没有可用线路且未显式禁用时，提示「没有可用的本机模型线路」。

「设置 → 模型与连接」的「模型服务」卡片在显式禁用时显示 `MODEL_DISABLED`，提示改用具体 provider 重新启动。报告尚未读取或内核只在握手中提供禁用标志时，卡片描述行也会给出提示。自动回退时状态为「默认模型线路不调用模型」。这两种情况下「测试模型」均不可用。

缺少任一项时才读取 `BOSS_HARNESS_CODEX_CONFIG`、`CODEX_HOME/config.toml` 或默认 `~/.codex/config.toml`，按此顺序选择文件，显式字段仍优先。读取 TOML 需要 Python 3.11+；若选用的 OpenAI 线路需要已有配置文件，而当前解释器不能解析 TOML，启动与自检都报 `MODEL_CODEX_TOML_UNAVAILABLE`。若 OpenAI 只是可选线路，模型目录跳过此线路，当前默认线路仍可启动。已有文件不可读或语法损坏时，选用该线路会明确报错，不退到其他 provider。文件不存在或缺少可用 profile 时继续检查端点与凭据，缺项会报错；未提供模型且没有可用文件模型时保留既有 `DEFAULT_MODEL`。

当前文件适配要求文件自身同时提供 `model`、`model_provider` 及该 provider 的 `base_url` 才形成可用 profile；凭据支持 provider 的 `experimental_bearer_token`，或由 `env_key` 指定环境变量名并从该变量读取；显式 `BOSS_HARNESS_OPENAI_API_KEY` 优先于文件凭据，文件内 `experimental_bearer_token` 优先于 `env_key`。OpenAI 线路仅支持 Responses：profile 的 `wire_api` 缺省或为空白时使用 `responses`，显式值忽略首尾空白并按不区分大小写处理；其他值或非字符串会以 `MODEL_CODEX_WIRE_API_UNSUPPORTED` 拒绝，不自动改用其他协议。应选择支持 Responses 的端点，不能仅修改标识来适配只支持 Chat Completions 的服务。尚未适配 Codex 的 OAuth。配置解析只读本地文件，不探测真实服务。

## 本地配置自检

此入口随当前源码提供。可以在命令行运行 `.venv/bin/boss-harness --check`，也可以在桌面内核启动失败后由主进程自动运行；两种方式使用同一套检查。与正常启动一样，可传入 `--provider` 与 `--model`，沿用上文的配置优先级。只核对不使用模型时，可显式传入 `--provider none`。CLI 自动模式在未设置 provider 且没有 Anthropic 凭据时会回退为 `none` 并给出警告；核对桌面默认的 OpenAI 线路时，请显式使用 `--check --provider openai`。若本机另有一条可解析的 OpenAI 线路且 `openai` 包可发现，警告的建议会改为点名该线路，并给出 `--provider openai`（桌面用 `BOSS_HARNESS_PROVIDER=openai`）的启动方式；线路无法解析时保持通用建议，配置可解析但 `openai` 包缺失时改为提示先安装内核依赖。在 `--check` 后加 `--format text` 可输出供终端阅读的分段文本（默认仍是 JSON，桌面解析不受影响），两种格式的退出码一致；文本结论行在存在错误时同时给出警告数量。退出码默认只区分两种结果：全部通过或只有警告为 0，存在错误为 2。脚本或 CI 需要把警告也视为未通过时加 `--strict`：存在错误仍为 2，没有错误但有警告为 1，全部通过为 0；`--strict` 只影响退出码，不改变报告内容，且只能与 `--check` 一起使用。显式 `--provider none` 本身会产生 `MODEL_DISABLED` 警告，因此严格模式适合核对已配置模型线路的环境。内核当前只支持 `--listen stdio://`（默认值）；传入其他端点时，自检、`--repair-state` 与正常启动都在执行任何动作前以退出码 2 结束并给出同一条固定说明，自检不输出报告。`--state-dir` 的值为空或只有空白时（常见于脚本中引用了未设置的变量）同样在三种模式下先以退出码 2 结束，不创建任何文件；省略该参数即使用默认状态目录，确实要用当前工作目录时显式写 `--state-dir .`。

命令向 stdout 输出单份 JSON 报告。`schemaVersion` 固定为 `1`；`version` 是当前内核源码版本，`protocolVersion` 是 JSON-RPC 协议版本（不是发布版本），`pythonVersion` 是实际运行自检的解释器版本；`ok` 表示 `checks` 中没有 `error` 项，`checks` 逐项提供固定检查码、`ok` / `warning` / `error` 状态、说明及处理建议。顶层字段及其含义：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `schemaVersion` | `1` | 报告结构版本；桌面自检解析器只接受该值。 |
| `version` | 字符串 | 内核 `__version__`，与同次源码构建的 npm 候选版本对应；不表示已发布到 npm 或 PyPI。 |
| `protocolVersion` | 字符串 | 进程边界的 JSON-RPC 协议版本，与桌面和协议包中的常量一致。 |
| `pythonVersion` | 字符串 | 运行 `--check` 的 Python 主版本、次版本与补丁版本。 |
| `ok` | 布尔值 | `checks` 中没有 `error` 时为 `true`；必须与检查项状态相符。 |
| `checks` | 数组 | 检查项列表；每项含 `name`、`status`、`code`、`message`、`hint`，名称在同一报告中不重复。 |

存在 `error` 时退出码为 `2`，全部通过或仅有警告时为 `0`。

| 检查项 | 固定检查码 | 检查范围与限制 |
| --- | --- | --- |
| 模型配置 | `MODEL_CONFIG_VALID` / `MODEL_DISABLED` / `MODEL_NOT_CONFIGURED` / `MODEL_CONFIG_INVALID` / `MODEL_CONFIG_INCOMPLETE` / `MODEL_SDK_UNAVAILABLE` / `MODEL_ENDPOINT_INSECURE` / `MODEL_EFFORT_UNSUPPORTED` / `MODEL_THINKING_IGNORED`，以及下表的具体错误码 | 只复用本地解析，不构造 SDK 或发起请求；缺少必需配置、文件损坏、非正输出上限或默认线路缺少模型 SDK 记为错误，显式 `none` 与自动回退分别记为禁用模型、未配置模型警告。显式 `http://` 且非本机回环的模型端点记为警告，说明凭据可能明文传输，不输出端点；显式推理强度不在内核支持的七档内、或与 `BOSS_HARNESS_MODEL_LIMITS` 为该模型声明的非空 `reasoningEfforts` 不符，或 Anthropic 线路的思考模式取值会被忽略时同样记为警告，不输出原值或声明内容。缺失 SDK 的检查只发现包，不导入或核对版本。禁用模型的处理建议是改用具体 provider 重新启动；自动回退只影响默认线路，不阻止其他已配置线路在会话内选用。 |

| 浏览器来源 | `BROWSER_SOURCE_VALID` / `BROWSER_SOURCE_INVALID` | 只校验 `BOSS_HARNESS_BROWSER_SOURCE` 的取值，不读取浏览器或 Cookie，也不验证上游是否支持该选项。 |
| 状态目录 | `STATE_DIRECTORY_VALID` / `STATE_DIRECTORY_IN_REPO` / `STATE_DIRECTORY_TILDE` / `STATE_DIRECTORY_LOW_SPACE` / `LEGACY_STATE_ENV_PRESENT` 及下文的目录错误码 | 只读核对实际状态路径的目录类型、所有权、父目录与 ACL 安全规则，以及基本访问条件；缺失路径只核对已有父目录，不创建或试写。实际使用的状态路径以 `~` 开头时（来自 `--state-dir` 或环境变量）记为警告，说明不会展开并建议改用绝对路径；旧变量 `BOSS_CLI_HARNESS_DIR` 显式非空时，在路径条件通过的前提下记为警告并建议迁移。路径与旧变量检查都通过后，还会读取状态目录或最近存在祖先所在文件系统的剩余空间，低于 512 MiB 时记为警告并建议释放空间，不输出本机路径或确切字节，也不阻止启动。 |
| 运行参数 | `RUNTIME_OPTIONS_VALID` / `APPROVAL_TIMEOUT_DEFAULTED` / `RETRY_CONFIG_DEFAULTED` 及下文的运行参数错误码 | 复用正常启动的解析，校验转向模式、模型请求上限、附件存储上限、模型容量与自动压缩环境变量的格式和取值；审批期限显式无效、模型重试配置显式无效或越界时记为警告并说明实际处理方式，不读取状态目录中的持久设置。 |

运行参数检查覆盖取值无效时会让内核启动失败的环境变量，按启动时的读取顺序报告遇到的第一个错误，修复后应再次运行：

| 固定检查码 | 环境变量与处理 |
| --- | --- |
| `STEERING_MODE_INVALID` | `BOSS_HARNESS_STEERING_MODE` 只能是 `all` 或 `one-at-a-time`；也可取消设置。 |
| `MAX_MODEL_REQUESTS_INVALID` | `BOSS_HARNESS_MAX_MODEL_REQUESTS` 去除首尾空白后须为 1 到 64 的十进制整数；空值或只有空白时使用默认值。 |
| `ATTACHMENT_STORAGE_LIMIT_INVALID` | `BOSS_HARNESS_MAX_ATTACHMENT_STORAGE_BYTES` 与 `BOSS_HARNESS_MAX_ATTACHMENT_STORAGE_OBJECTS` 去除首尾空白后须为 1 至 `2^63-1` 的十进制整数；空值或只有空白时使用各自默认值。 |
| `MODEL_LIMITS_INVALID` | `BOSS_HARNESS_MODEL_LIMITS` 的 JSON 结构、`provider/model` 键或容量取值无效；空值或只有空白视为未设置。格式见[内核与业务契约参考](TECHNICAL_REFERENCE.md)。 |
| `COMPACTION_CONFIG_INVALID` | `BOSS_HARNESS_COMPACTION` 的 JSON 字段、类型或取值范围无效；空值或只有空白视为未设置。格式见[内核与业务契约参考](TECHNICAL_REFERENCE.md)。 |

报告不回显这些变量的原值。检查只判断格式与取值范围，不核对摘要线路的凭据、声明的容量是否与模型服务一致，也不读取 `config.json` 中的持久自动压缩设置。

模型配置错误进一步提供以下固定码；命令行与桌面显示同样的说明和建议：

| 固定检查码 | 含义与处理 |
| --- | --- |
| `MODEL_ENDPOINT_MISSING` | OpenAI 线路缺少端点；设置 `BOSS_HARNESS_OPENAI_BASE_URL`，或在有效 Codex profile 的 provider 中配置 `base_url`。 |
| `MODEL_CREDENTIAL_MISSING` | OpenAI 线路缺少凭据；设置 `BOSS_HARNESS_OPENAI_API_KEY`，或在有效 Codex profile 的 provider 中配置 `experimental_bearer_token` 或 `env_key` 指向的环境变量。 |
| `MODEL_CODEX_UNREADABLE` | 无法读取 Codex 配置文件；核对配置路径与读取权限。 |
| `MODEL_CODEX_TOML_UNAVAILABLE` | 当前解释器缺少 Codex TOML 解析能力；改用 Python 3.11+，或显式设置 OpenAI 模型、端点与凭据以跳过该文件。 |
| `MODEL_CODEX_INVALID_TOML` | Codex 配置的 TOML 格式无效；检查语法与文件编码。 |
| `MODEL_CODEX_NOT_FILE` | Codex 配置路径不是普通文件；将 `BOSS_HARNESS_CODEX_CONFIG` 指向文件，或核对 `CODEX_HOME` 下的 `config.toml`。 |
| `MODEL_CODEX_WIRE_API_UNSUPPORTED` | Codex profile 声明了内核不支持的协议或值类型；选择支持 Responses 的端点并将 `wire_api` 设为 `responses`，或使用完整显式 OpenAI 配置跳过该文件。 |
| `MODEL_PROVIDER_UNKNOWN` | `BOSS_HARNESS_PROVIDER` 的取值无法识别；设为 `none`、`anthropic`、`openai` 或 `codex`，或取消设置以自动选择。`auto` 与取消设置等价，不视为未知取值。 |
| `MODEL_MAX_TOKENS_INVALID` | `BOSS_HARNESS_MAX_TOKENS` 不是正整数；设为正整数，或取消设置以使用默认值。 |
| `MODEL_REQUEST_TIMEOUT_INVALID` | `BOSS_HARNESS_MODEL_REQUEST_TIMEOUT_SECONDS` 不是 1 到 3600 的整数；修正取值，或取消设置以使用默认值。 |
| `MODEL_SERVER_FALLBACK_INVALID` | Anthropic 线路的 `BOSS_HARNESS_SERVER_FALLBACK` 不是可识别的开关写法；设为 `1` / `true` / `yes` / `on` 或 `0` / `false` / `no` / `off`，或取消设置以按端点取默认值。 |
| `MODEL_PROMPT_CACHE_INVALID` | Anthropic 线路的 `BOSS_HARNESS_PROMPT_CACHE` 不是可识别的开关写法；设为 `0` / `false` / `no` / `off` 以关闭，或 `1` / `true` / `yes` / `on` 以开启，或取消设置以使用默认的开启。 |

一次自检只报告解析时遇到的第一个模型配置错误，修复后应再次运行；业务 CLI、浏览器来源与状态目录仍独立检查。配置来源与覆盖顺序不变：完整显式模型、端点和凭据会跳过 Codex 文件；需要补全时，损坏或不可读的已有文件以及可用 profile 中不支持的 `wire_api` 会明确失败，文件缺失则继续核对必需字段。正常启动对已登记的模型配置错误在 stderr 输出同一固定码与静态说明，退出码为 `2`。供应商拼写、输出上限、请求期限、服务端回退开关与提示缓存开关错误使用上表的专用码；其余未细分的错误继续返回 `MODEL_CONFIG_INVALID`；Anthropic 缺少必需字段仍为 `MODEL_CONFIG_INCOMPLETE`，提示只列该线路的模型 id 与 `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN`，OpenAI 线路才提及端点与有效 Codex profile。报告结构与 `schemaVersion: 1` 不变，按检查码处理的调用方应保留未知码的通用错误展示。

状态目录检查使用正常启动实际选择的路径：`--state-dir` 优先于 `BOSS_HARNESS_DIR`，其次为旧变量 `BOSS_CLI_HARNESS_DIR`；两个环境变量为空或只有空白时都视为未设置并继续回退，均未设置或均为空白时，新默认目录不存在而旧默认目录存在才沿用旧目录。相对路径按启动工作目录解析，内核不展开 `~`（未加引号时由 shell 展开后才传入），符号链接沿用正常启动的真实路径解析方式。本次检查使用的路径以字面 `~` 开头时，无论来自 `--state-dir` 还是环境变量，自检在路径条件通过的前提下报 `STATE_DIRECTORY_TILDE` 警告并建议改用绝对路径；此时正常启动会在工作目录下创建名为 `~` 的目录。显式 `--state-dir` 指向其他路径时不因残留环境变量报警。自检从状态目录自身向上查找 Git 仓库，解析后位于任一仓库内时报告 `STATE_DIRECTORY_IN_REPO` 警告并建议移到仓库外，工作目录在哪里不影响结论：会话记录、工具结果与附件不应进入可能被提交的目录。多个状态目录警告同时成立时只报一个，顺序为 `STATE_DIRECTORY_IN_REPO`、`STATE_DIRECTORY_TILDE`、`LEGACY_STATE_ENV_PRESENT`、`STATE_DIRECTORY_LOW_SPACE`；处理后重新运行可看到下一项。旧变量显式非空时，自检在路径条件通过的前提下报 `LEGACY_STATE_ENV_PRESENT` 警告；两者同时设置时以 `BOSS_HARNESS_DIR` 为准，路径条件失败时仍优先报告目录错误码。路径条件、`~` 提示与旧变量提示都通过后，自检还会读取状态目录或最近存在祖先所在文件系统的剩余空间；低于 512 MiB 时报 `STATE_DIRECTORY_LOW_SPACE` 警告，不输出本机路径或确切字节。无法读取文件系统信息时保持 `STATE_DIRECTORY_VALID`，不新增失败。

| 目录错误码 | 含义与处理 |
| --- | --- |
| `STATE_DIRECTORY_NOT_DIRECTORY` | 状态路径或父级被文件等非目录对象占用；保留已有文件，核对配置并选择独立目录。 |
| `STATE_DIRECTORY_ACCESS_DENIED` | 已有状态目录缺少读取、写入或进入权限，或缺失路径的已有父目录不可写、不可进入；核对权限后重新连接。 |
| `STATE_DIRECTORY_INVALID` | 路径或目录安全条件不符合内核规则，例如根目录、非当前用户拥有的目标目录、允许他人修改的目录或 ACL，以及路径无法解析（如符号链接环）；选择可信的独立目录，不要放宽权限。 |
| `STATE_DIRECTORY_UNSUPPORTED` | 当前系统或解释器缺少内核私有状态机制要求的文件或 ACL 能力。 |
| `STATE_DIRECTORY_UNAVAILABLE` | 其他文件系统错误导致无法完成核对；检查路径、文件系统与权限。 |

已有目录沿用正常启动的安全规则，不要求统一改成某一权限值；自检也不会自动收紧权限。目录缺失时只核对已有父目录，后续目录由正常启动创建。路径无法解析（如符号链接环）同属无效路径：自检报 `STATE_DIRECTORY_INVALID`，正常启动与 `--repair-state` 都以固定中文说明和退出码 2 结束，不打印 Python 回溯或本机绝对路径。检查不获取占用锁、不打开索引或会话、不尝试真实写入；磁盘空间只按文件系统剩余空间做 512 MiB 阈值提示，不估算本次会话或附件的实际需求，通过也不证明路径没有被另一内核占用或索引与会话完整，实际启动仍是最终核对。

从命令行直接启动内核而在构造阶段失败时（状态目录不可用、系统不满足私有状态目录要求、运行参数取值无效等），stderr 在失败行之后会追加一行固定提示，建议用相同参数与环境运行 `boss-harness --check`。启动失败与 `--repair-state` 失败遇到本地文件错误时，失败行给出固定中文原因与系统错误名（如「本地文件权限不足（EACCES），操作未完成。」），不回显路径或目录名，可直接用于报告问题。模型线路构造失败与浏览器来源配置失败的失败行同样处理，并抹掉 `Bearer …`、`sk-…`、`api_key=…` 等凭据形态的文本；脱敏按形态识别，贴出前仍建议自行检查。解释器缺少 `anthropic` 或 `openai` 等内核依赖时，stderr 会点名缺失模块并给出 `uv pip install --python .venv/bin/python -e ./harness`，退出码同为 `2`。

报告不包含端点、密钥、模型自定义值、本机路径、会话内容或异常原文，可用于报告安装问题。自检不创建状态目录、不修改权限、不读取会话、不写入索引，与 `--repair-state` 互斥。本地检查仅覆盖上表五项；模型检查用 `importlib.util.find_spec` 核对默认线路所需的 `anthropic` / `openai` 包是否可发现，但不导入 SDK、不核对已安装版本，也不核对其余取值无效时回退默认值的参数。通过不代表模型可连接、认证有效、平台已登录或真实工具已验收；这些操作应分别在获得授权后核对。

## 桌面启动失败时的自检

本地内核未能完成启动时，桌面会自动运行一次上述自检，每个失败周期一次。本次连接在握手完成前失败才运行，包括曾经就绪后重新启动失败；自动重试期间沿用同一结论，就绪或点「重新连接」后作废，恢复连接后提示自动清除。

- 自检使用与内核相同的解释器、工作目录与环境（只额外设置输出编码），因此结论与内核实际使用的配置一致；它不调用模型、不执行业务 CLI、不访问招聘平台。
- 错误项的说明与建议显示在底部提示条，以及「设置 → 模型与连接」的「招聘 Harness」行；后者按「错误 → 警告 → 通过」列出明细与检查码，同类项保留自检报告的原始顺序，方便先找到导致启动失败的原因。命令行报告顺序不变。
- 报告带 `version` / `protocolVersion` / `pythonVersion` 时，「招聘 Harness」行会在明细前显示「自检报告：内核 … · 协议 … · Python …」，便于核对桌面、内核与解释器是否同源；字段缺失或不合规时不显示，不猜测版本。报告中的协议版本与桌面使用的协议常量不一致时，同一位置会给出「协议版本不一致」提示并列出两侧版本，提示桌面与内核可能来自不同构建。
- 自检区域提供「复制自检结果」：复制内容为纯文本，包含提示标题、自检报告版本、协议不一致提示（如有）、逐项状态与检查码以及处理建议；只使用界面已展示的静态自检字段，不包含 stderr、异常原文、端点、凭据、本机路径或会话内容。写入成功显示「已复制」，失败显示可读原因。
- 提示条区分「内核未能完成启动」与「就绪后断开」：前者说明自动重试是否仍会继续；后者保留「结果未确认的对外操作请先核对平台状态」，自动恢复重新就绪后清除。
- 界面不展示内核 stderr、异常原文、端点、凭据或本机路径，只使用上表的固定检查码与静态建议。
- 自检未发现配置错误时仍可能启动失败，说明问题在已返回检查项的范围之外（例如依赖未装好、实际写入失败、磁盘空间在阈值之上仍被写满或目录已被另一内核占用），请按提示逐项排查。
- 结论只用于排查，不替代重新连接。安装内核依赖、修正配置文件或目录条件后可重新连接；解释器与相关环境变量在应用启动时确定，更换解释器或修改这些变量后需重启应用。

此外，「设置 → 模型与连接」的「本地配置自检」行可随时运行同一份自检，不要求内核已连接：解释器、工作目录与环境沿用应用启动时的选择，渲染层不传任何参数。同一时刻只保留一个自检进程，连续点击共用同一份在途结论；启动失败自检尚未结束时先等它退出；退出应用时会结束仍在运行的自检进程。运行期间按钮显示进度并禁用；结果到达时显示与 `--format text` 同口径的总体结论与本机运行时刻（「通过」「通过，N 项警告」或「发现 N 个错误、M 项警告」），按「错误 → 警告 → 通过」列出名称、说明与检查码，报告带版本字段时显示内核、协议与 Python 版本，协议不一致时同样提示，超时、进程启动失败或输出不合规沿用上述固定说明且不显示结论。结果不持久化，重新进入页面不会显示旧的运行时刻。结果可复制为纯文本，只含界面已展示的字段，标题包含运行时刻与结论，不可用结果把固定说明一并复制；新的结论会作废旧回执。自检只读取本地配置，不调用模型、不运行招聘 CLI、不访问招聘平台，通过不代表模型可连接、认证有效或平台已登录。

## 单次模型请求期限

OpenAI Responses 与 Anthropic Messages 的单次传输默认最多运行 600 秒，可用 `BOSS_HARNESS_MODEL_REQUEST_TIMEOUT_SECONDS` 设置为 1–3600 的整数秒。该 wall-clock 总时限覆盖连接建立和流式响应；SDK 原有的 30 秒连接/读取空闲时限仍然生效，周期性 SSE 心跳不会延长总时限。

超时不会标记为用户取消，也不进入上下文溢出恢复。后台清理在期限内确认完成时，它作为可重试传输错误结束；若清理仍未完成，内核停止自动重试并保留该传输的资源额度。OpenAI 仅在尚无可见输出且清理已确认时遵循既有重试策略，每次 attempt 各自重新计时；Anthropic 不新增自动重试。这不是跨重试或 Agent 自动恢复的共享总预算。

每个内核进程最多保留 8 个模型传输，业务回合、摘要与连接检查共同使用；未完成后台清理的传输也占用额度，满额时新请求在发出前失败。流事件队列最多保留 64 项、估算共 4 MiB，单事件最多 2 MiB。该预算针对 SDK 已解码对象，不能限制 SDK 解码单帧时的临时内存或整个进程 RSS。

## 其他运行参数

以下环境变量在内核启动时读取一次，修改后需重启内核（桌面需重启应用）。桌面启动的内核继承应用进程的环境变量。

| 变量 | 作用 | 默认值与范围 | 取值无效时 |
| --- | --- | --- | --- |
| `BOSS_HARNESS_MAX_TOKENS` | 单次模型请求的输出上限，同时作为上下文预算中的输出预留。 | 64000；正整数；空值或只有空白时使用默认值。 | 启动失败，自检报 `MODEL_MAX_TOKENS_INVALID`。 |
| `BOSS_HARNESS_MAX_MODEL_REQUESTS` | 单个回合最多发起的模型请求数；回合自带的上限只能在此基础上收紧。 | 6；去除首尾空白后须为 1–64 的十进制整数，空值或只有空白时使用默认值。 | 启动失败，自检报 `MAX_MODEL_REQUESTS_INVALID`。 |
| `BOSS_HARNESS_RETRY_ATTEMPTS` | 模型请求在首个输出前遇到可重试失败时的最多尝试次数，含首次；设为 `1` 即不自动重试。 | 3；1–10。 | 未设置、为空或只有空白时使用默认值；不是整数时使用默认值；超出范围时收敛到 1 或 10；自检报 `RETRY_CONFIG_DEFAULTED` 警告。 |

| `BOSS_HARNESS_APPROVAL_TIMEOUT` | 需审批的工具调用等待裁决的期限（秒），到期后该审批按过期处理，不执行调用。 | 300；正数，可带小数。 | 未设置、为空或只有空白时使用默认值；不是数字、非有限值或不大于 0 时使用默认值；自检报 `APPROVAL_TIMEOUT_DEFAULTED` 警告。 |
| `BOSS_HARNESS_PYTHON` | 桌面应用启动内核与运行自检所用的 Python 解释器，需为 3.10 及以上并已安装内核。 | 未设置、为空或只有空白时，优先选仓库的 `.venv/bin/python`；目标不是普通文件或当前进程无权执行时回退到 PATH 上的 `python3`。显式路径去除首尾空白后优先使用。 | 解释器无法启动时桌面提示未能启动 Python 解释器；显式路径失败时不会自动回退。 |
| `BOSS_HARNESS_STEERING_MODE` | 回合运行中排队的转向消息如何进入当前回合：`all` 在每个投递点注入全部排队转向，`one-at-a-time` 每次只注入最早一条。 | `all`；未设置或为空时取默认值，取值区分大小写且不去除空白。 | 启动失败，自检报 `STEERING_MODE_INVALID`。 |
| `BOSS_HARNESS_MAX_ATTACHMENT_STORAGE_BYTES`、`BOSS_HARNESS_MAX_ATTACHMENT_STORAGE_OBJECTS` | 状态目录中持久附件的总字节数与文件对象数上限；降低上限不影响读取已有附件，只拒绝新增的唯一内容。 | 512 MiB、4096 个对象；去除首尾空白后须为 1 至 `2^63-1` 的十进制整数，空值或只有空白时使用各自默认值。 | 启动失败，自检报 `ATTACHMENT_STORAGE_LIMIT_INVALID`。 |

自动重试的单次等待最长 8 秒；模型服务返回建议等待时间时以其为准，同样不超过 8 秒。重试只发生在向会话产出首个内容之前，并受回合内共享的模型恢复预算约束，与[单次模型请求期限](#单次模型请求期限)相互独立。实际生效的审批期限可在握手结果的 `approval.timeoutSeconds` 中核对；转向模式与附件存储上限的生效值由 `config/read` 的 `steeringMode`、`maxAttachmentStorageBytes` 与 `maxAttachmentStorageObjects` 返回，附件存储的计量与拒绝行为见[内核与业务契约参考](TECHNICAL_REFERENCE.md#持久附件存储)。

桌面根据内核通知显示重试等待与结束状态；兼容路径缺少回合状态时仍保留等待提示，收到明确中断时显示「已停止」，不会把缺省状态当成重试已结束。自动重试策略不变。

审批期限与两项重试配置的无效取值不会让启动失败，自检以 `APPROVAL_TIMEOUT_DEFAULTED` 或 `RETRY_CONFIG_DEFAULTED` 警告说明已回退或收敛；配置看似未生效时，请先核对取值是否符合上表。模型线路与凭据见[模型配置来源](#模型配置来源)，请求期限见[单次模型请求期限](#单次模型请求期限)，浏览器来源与两类状态目录见[上游 CLI 设置](#上游-cli-设置)；模型容量 `BOSS_HARNESS_MODEL_LIMITS` 与自动压缩 `BOSS_HARNESS_COMPACTION` 的 JSON 格式分别见技术参考的[模型容量与请求预算](TECHNICAL_REFERENCE.md#模型容量与请求预算)和[自动压缩与溢出恢复](TECHNICAL_REFERENCE.md#自动压缩与溢出恢复)。

## 停止内核

从命令行直接运行内核（`boss-harness`，经标准输入输出通信）时，结束它的标准输入就是正常关闭：内核停止接收请求、中断运行中的回合并写完会话记录，以退出码 0 结束。桌面应用退出时走的也是这条路径：先结束标准输入并等待内核关闭；关闭卡住时最多等约 3.5 秒，由客户端的 `SIGTERM` / `SIGKILL` 升级收尾，不会留下孤儿内核。

用 `SIGTERM`、`SIGHUP` 或 `Ctrl+C` 停止内核时，内核先终止进行中的招聘 CLI 调用并写完会话记录，再结束进程。结束方式仍是这个信号本身：从 shell 看到的状态与信号未被处理时相同（例如 `SIGTERM` 为 143），stderr 末尾多一行 `[harness] 收到 SIGTERM，已按关闭流程停止`，`Ctrl+C` 不再打印回溯。被终止的调用在会话里带 `CANCELLED` 标记：只读查询记为失败，已经批准的发送类调用记为结果未知。已经发出的操作可能生效，重新打开会话后仍需先核对平台状态，不要直接重试。

信号到达 5 秒后关闭仍未完成时，内核会被强制结束，此时进程的结束方式是 `SIGALRM`，会话记录可能停在结束前的状态。经 `nohup` 启动等已经忽略 `SIGHUP` 的环境里，内核继续忽略它。`kill -9` 不经过这段流程：内核立即结束，进行中的招聘 CLI 调用留在后台继续运行，重新打开会话后这次调用显示为结果未知，需要核对平台状态。上述信号处理只在 macOS 与 Linux 上生效；Windows 上的行为与此前相同。

## 聊天链接与代码

聊天回复中的 Markdown 链接（`[说明](目标地址)`）可包含成对或嵌套圆括号，也可用反斜杠转义圆括号（`\(`、`\)`）。链接尚未闭合时保留为可见文本，流式输出补齐结束括号后才生成链接，避免打开被截断的地址。

普通链接与来源编号样式的链接都只会把 HTTP、HTTPS、mailto 地址交给系统打开；其他协议保持不可打开。行内代码和代码围栏中的链接语法按代码显示，不生成可点击链接；代码块可通过「复制代码」按钮复制。

复制成功后显示「已复制」，失败时显示「复制失败」，悬停可查看原因，约 2 秒后复位。同一回复中连续复制多个代码块时，新点击会清掉上一轮提示，只有最近一次点击的结果可以更新反馈，较早请求的迟到成功或失败不会覆盖它。切换文件等操作重置反馈后，旧回执也不会让提示重新出现。

## 资料库复制

在导航栏打开「资料库」，点击工具来源右侧的「复制」可复制完整来源编号；打开文件变更引用的详情后，点击「复制路径」可复制完整路径。文件变更引用目前只由示例会话提供，页面不读取文件正文。

复制真正成功后，提示显示在对应来源行或文件详情中；失败时显示「复制失败：」及原因，约 2.6 秒后复位。连续点击多个复制按钮时，新点击会清除旧提示，只有最近一次点击的回执可以更新结果，同一按钮重复点击也一样。切换页面、打开或关闭文件详情会清除提示并使旧回执失效，返回时不会重新出现。这只保护界面反馈，不会取消已经发起的系统剪贴板写入。

## 聊天内查找

在聊天中按 `⌘F` / `Ctrl+F` 打开查找栏，匹配当前会话中实际渲染的用户输入与模型段落，支持 `Enter` / `Shift+Enter` 前后跳转。状态行按「处命中」计数，同一消息内的多处命中可逐个停靠。

默认只匹配可见正文：计数与高亮都不包含默认收起的思考块、工具块及其内部折叠内容，避免状态行大于屏幕上可见的命中数、当前命中落在看不见的文字上。折叠块标题（`summary`）始终可见，仍参与匹配。勾选「含工具、审批与思考」后，匹配范围扩展到思考内容、工具调用详情与审批卡字段；此时计数包含折叠内容，跳转到对应消息会自动展开命中所在的块，当前命中以另一种颜色高亮。关闭查找栏会清除高亮。

## 发送回执与核对

在已有会话直接发送消息，内核明确拒绝时提示发送失败；回执不可读或连接异常时提示提交结果尚未确认，两者都保留来源草稿并重新读取会话状态，不自动重发。未知回执不能证明消息未受理，请先核对聊天记录再决定下一步。

失败提示跟随发起发送的会话：回执到达前切到另一会话时，提示标明「会话「标题」：」；切回来源会话后恢复原文，另一会话不会保存这条失败。显式关闭提示或来源会话新回合开始后清除旧记录。提示只保存在本次应用内存中，重启后以会话记录与工具结果为准。

从首页创建新会话时，首条消息被内核明确拒绝后会话已经建立：提示会说明会话已创建、草稿仍保留在首页，并指出可从会话列表打开该会话核对后重试，不会把整个创建说成失败；具体拒绝原因保存在该会话的错误记录中，打开会话可见。此时不要在首页直接重发，否则会再建一个空会话。

若随后重新读取会话也失败，提示会同时保留原始发送原因和读取失败原因：明确拒绝仍显示拒绝原因与内核码，未知回执仍说明「提交结果尚未确认」。回执未知时，保留的内容不证明消息未受理，请稍后重新打开来源会话核对，再决定下一步，不会自动重发。双重失败提示、读取失败提示的内容与后台提示的清理按同一会话归属。读取失败原因只显示内核返回的说明，不再包含主进程拼接的调用前缀；关闭后台提示会清除其来源会话的记录，切回不再重新出现；来源会话新回合开始或删除时，正在显示的旧提示一并清除。

## 审批回执与核对

审批卡提交后会锁定等待回执。内核明确受理时显示已提交或已处理；明确拒绝时按原因说明是否需要刷新会话。断连或回执不可读时只知道结果尚未确认，不能据此断定审批未送达或工具没有执行。请先核对审批与工具结果，不要直接重复提交；切回发起会话后仍能看到手动审批的核对提示。真实会话里的审批缺少有效标识时按钮禁用并提示刷新会话核对：该记录无法定位到内核审批，点击不能只改本地状态并显示成已有结论；示例模式的无标识审批卡仍按本地演示处理。

「本次会话记住选择」的自动批准遇到未知回执时也使用相同提示，并显示该次审批供核对，不自动重发。自动批准明确被拒绝或结果未知时，说明保存在来源会话的输入区：在回执到达前切到另一会话，或请求原本就来自后台会话时，提示均留给来源会话，切回后仍可核对。提示保存在本次应用内存中，重启后应核对会话记录与工具结果；新的手动提交会清除上一次提示。对外操作仍需逐次确认，记住选择不改变工具授权。审批是否需要逐次确认以内核给出的布尔标记为准：标记缺省或不可读时，实时审批卡、恢复会话后的审批卡与自动批准都按需要逐次确认处理，不显示成可记住。

迟到回执保护：若同一审批的裁决通知、工具完成通知或已恢复会话记录先给出已批准、已拒绝或已过期结论，随后到达的自动批准拒绝或未知回执不会将其改回待审批。切回会话且快照读取失败时也保留已知结论，不重新开放操作；尚无该次结论时仍显示审批卡供核对。回执原因继续保存在来源会话；已批准只说明审批决定，工具是否执行及结果如何仍需单独核对。

参数无法作为命令行传递时不会出现审批卡：字符串参数含空字符的调用在审批之前就被内核以参数错误拒绝，只留下未执行的工具条目，并说明是无法传递的字符而不是笼统的参数不符。已批准但子进程在实际启动前失败（例如参数无法编码）的调用显示为未执行并暂停本回合，不会提示「可能已生效」。

自动批准被内核明确拒绝时，提示与手动路径一样按拒绝码区分，不再一律写「请手动确认」：

| 拒绝码 | 提示要点 | 是否重读会话 |
| --- | --- | --- |
| `APPROVAL_CLOSED` | 审批所属回合已结束或会话已归档，不再接受裁决 | 是 |
| `APPROVAL_CONFLICT` | 该审批已按相反决策处理 | 是 |
| `APPROVAL_NOT_FOUND` / `APPROVAL_INVALID` / `APPROVAL_AMBIGUOUS` | 审批不存在、记录无效或重复 | 是 |
| `APPROVAL_EXPIRED` | 审批已失效，不再接受裁决 | 是 |
| `APPROVAL_BUSY` | 审批仍由活动回合持有，先停止或等待，不要反复提交 | 否，避免全量快照覆盖流式输出 |
| 无原因码的明确拒绝 | 未被受理，刷新会话后再处理 | 否 |

同一审批若已经有结论，提示会说明「该审批已有结论，界面未重新开放操作」，并继续要求核对工具结果；结果未知（断连、回执不可读）仍走先核对、不直接重复提交的文案。刷新只用于让内核持久化的结论落到卡片，不产生新的裁决，也不代表工具已经执行。

工具卡显示的执行状态标签来自会话条目；损坏的持久工具记录不会生成模型无法读取的结果引用，也不会突破模型结果预算。模型看到的工具结果还会带有执行状态与投递 / 重试提示：未执行或审批未通过的调用被视为未送达、可安全重试；结果不确定的写操作被视为已派发且不可直接重试；只读工具的普通失败通常没有对外副作用，写工具失败仍须先核对平台状态。不存在「错误码等于可重试」的推断：成功、失败或断连都可能留下未知的外部结果。看到「结果不确定」「无法确认已保存」等提示时，先查看会话记录和平台实际状态，再决定是否发起新动作；Harness 不会自动重放工具或审批。字段契约见[内核与业务契约参考](TECHNICAL_REFERENCE.md#大结果与会话恢复)。

## 桌面会话的执行权限

桌面新建的会话固定使用只读工具策略：内核向模型提供 13 个只读工具（含能力发现）和 1 个只读内核结果分段读取工具，`boss_hr_greet` 不在工具清单中，因此不会出现写操作审批卡或写操作请求；输入区左侧「执行权限」菜单显示「只读会话」，并说明该限制随会话保存、重启和创建分支后继续生效。当前版本不提供在桌面切换策略的入口。

逐次审批只出现在以审批策略创建的会话中：调用 `thread/start` 时传 `toolPolicy: "approval"`（该参数缺省时即 `approval`，`readOnly` 为只读）。这类会话由其他客户端创建后，桌面会像只读会话一样列出并读取，在聊天中展示审批卡并接受裁决；从它们创建的分支沿用来历会话的策略。审批结论只代表操作获准，工具是否执行及结果如何仍需按「审批回执与核对」核对。

## 技能与队列

把运行时技能放在工作区 `.boss-harness/skills/<id>/SKILL.md`（旧 `.boss-cli/skills` 仍兼容读取），可用 frontmatter 的 `name` 与 `description` 提供菜单名称和说明。在输入区选择技能后，它会随一次直接发送或「排到后续回合」的队列消息进入该回合的提示上下文；技能不会执行目录脚本，也不会扩大工具清单或审批范围。目录最多发现 100 个普通技能文件，每个文件最多 64 KiB；每次最多选择 10 项。`skills/list` 只为菜单与检索提供投影：名称最多 200 字符、描述最多 500 字符，超长部分截断并带 `nameTruncated` / `descriptionTruncated`，完整正文仍在「技能与工具」页或 `skills/read` 中读取。未能加载的目录单独成清单，不受已加载技能数量影响；可加载技能超过 100 个展示上限时返回 `skillsTruncated`，未加载项超过展示上限时返回 `problemsTruncated`，目录总数超过单次扫描上限（800 个目录项）时返回 `candidatesTruncated`；目录数恰好顶到窗口上限但已全部检查时不会标记截断。界面据此说明清单不完整，不会把部分清单说成总数。转向当前回合的消息不使用技能，已选技能时会提示清除或改为后续回合。技能目录尚未读取、内核断开或读取失败时，已选技能标签保持可用显示，不会标注「已不在当前技能目录中」；只有成功读取的目录才据此标注缺失技能，目录确认为空时菜单提供「清除不可用技能」。这一状态展示按当前内核返回。

`SKILL.md` 的 frontmatter 以独立的 `---` 行开始和结束，文件可带 BOM 或使用 CRLF 换行；`description` 等取值中出现的 `---` 属于内容，不会提前结束 frontmatter。缺少起始或结束分隔线时，名称回退为目录名、描述为空。在「技能与工具」页新建、保存或删除技能后的确认提示只在当次停留期间显示，切到其他页面即清除，返回时不会重新出现。

任务运行时，可将新消息转向当前回合，或排到当前回合结束后；停止任务是独立操作。停止请求携带界面正在展示的回合 id：如果该回合在你点击后已经结束、排队的后续回合已经开始，内核会明确拒绝这次停止并保持新回合运行，提示「本次没有中断任何回合」，而不是把停止静默落到你没看到的回合上。停止失败与「没有可停止的回合」按发起停止的会话保存：回执到达前切到另一会话时，提示会标明所属会话；切回该会话仍能看到原文，不会只剩侧栏徽标。内核明确拒绝（例如目标回合已变化）与回执无法确认分开说明；两者都不会自动重发停止。若随后重新读取会话也失败，提示会同时保留停止原因与读取失败原因：明确拒绝仍显示内核码与「没有中断任何回合」，未确认仍说明不会自动重复停止；读取失败不证明停止已经生效，请重新打开来源会话核对后再决定下一步。受理停止不产生失败提示，重新发起回合会清除该会话的旧提示；停止请求在途或已被受理、回合尚未结束时，按钮禁用并显示「正在停止任务」，重复点击会被忽略，不会误报「未找到可停止的任务」；请求失败或内核回报没有可停止回合时立即恢复。多个会话同时停止时各自保持「正在停止任务」，切到别的会话再切回来仍能看到，某个会话停止结束只恢复该会话的按钮。队列状态会持久化，尚未投递的项目可以撤回。启动失败且确认输入尚未写入会话的后续回合项可直接「重新排队」：沿用原输入与技能创建新队列消息，并撤回旧项；其余失败、结果不确定或结算异常时，队列会暂停并要求先核对；不会自动重放工具、审批或招聘平台操作。相同 `clientUserMessageId` 会关联原请求，输入已接受不表示回合已成功。仍在排队的消息可在投递前经 `queue/update` 编辑正文：只接受 `queued` 项，保留技能、自动压缩覆盖与请求编号，正文仍限 1–100000 字符并受待处理队列字节上限约束；桌面编辑截断项时会先读取完整正文。内核声明 `queueSteer` 时，排队中的后续消息还可「转为当前回合」：内核在同一条记录上原子改为 steering，保留正文与请求编号；带技能或自动压缩覆盖的项会被明确拒绝，当前没有运行回合或断连时按钮禁用并说明原因。会话读取与 `queue/list` 优先返回暂停项，再返回最近的排队 / 投递中项（待处理项单次最多 200 项），名额允许时另返回最近 50 个已终结项；正文预览最多 600 字符并标注截断，重新排队经 `queue/get` 读取该项完整正文与技能，不会复用预览。内核报告的总数或待处理数大于已载入项时，界面按截断处理；即使截断标记缺失，也不会把未载入的消息判为「队列中不存在」，提交核对会如实显示「无法确认」。

## 暂停队列批量处理

队列里有至少两条可重试的暂停消息时，可选择「重新排队全部暂停项」；有至少两条暂停消息时，也可选择「撤回全部暂停项」，核对数量和预览后再确认。批量入口只处理暂停项，排队中与投递中的消息仍按单条操作。

批量操作按列表顺序逐条执行，进度显示已处理数量。处理中可点「停止剩余」：当前这一条完成后不再开始下一条，已成功的操作不回滚，其余暂停消息保留；遇到明确拒绝或结果未确认也会停止。切换会话会停止发起后续请求，已完成的结果仍属于原会话。

重新排队先创建新消息，再撤回旧项。如果新消息已受理、旧项撤回未确认，这一条仍计入已重新排队数量，但批量会停止；单条操作也会显示部分完成提示，切回发起会话后仍可查看。操作结果显示在队列标题下方，先看到核对说明，再浏览队列项。请先刷新队列，核对并撤回仍保留的旧项，不要重复重新排队。回执不可读不代表旧项一定没有撤回；仅刷新失败而两步写入均已确认时，按本地结果更新并提示列表可能过期，不把新消息说成未受理。

刷新失败后的计数保护：已有持久待处理总数时，按新项加入与旧项确认撤回的结果增减，不用面板已载入数覆盖全量；旧项撤回未确认时继续计入旧项。截断投影且内核未报告总数时，继续保留「可见待处理」口径。该本地展示不代表队列已经刷新，请按提示核对。

单条撤回需确认，撤回后正文不会自动恢复。结果未确认时先核对队列状态；不要将它当成明确未受理并直接重复提交。批量期间单条操作和刷新入口会暂时禁用，避免对同一批条目交叉修改。

## 会话与阅读状态

应用启动后会恢复上次打开且仍在列表中的会话；如果记录已删除或不再列出，则停留首页。回到首页的新建任务入口会结束这次自动恢复目标。恢复会话只读取历史，不会自动发起模型或招聘平台操作。

本次应用运行期间，切回会话会恢复已缓存的消息与队列、滚动位置、工具 / 思考块展开状态和聊天内查找。切到后台失败的会话时仍能查看该会话的失败原因；关闭提示后不再重复显示。输入区正文与技能另按草稿规则写入本机存储；阅读位置等内存状态不代表重启后全部恢复。

侧栏会话菜单的「复制 → 聊天标题 / 会话 ID」把内容写入系统剪贴板，结果显示在侧栏底部，约 2.6 秒后复位。连续复制多个内容或重复复制同一内容时，新点击会使旧回执失效，只有最近一次点击可以更新提示，较早请求的迟到成功或失败不会覆盖它。

最近聊天页与 `⌘K` 搜索窗口保持打开时，每 15 秒按本机时间更新相对时间；异步消息命中到达时保留已选中的结果。关闭或离开后停止本地计时，不额外读取内核。

内核支持会话内分支时，可在「会话分支」查看端点、切换位置，并按需为被放弃分支生成摘要（默认关闭，启用会调用模型）。摘要期间聊天区显示进度与「取消摘要」，取消不撤销已经完成的分支切换。旧任务或旧连接的迟到状态读取不会覆盖新任务，取消继续作用于当前显示的任务；这一轮询保护与当前内核版本无关。断连后的任务结论仍需在恢复连接后核对，迟到回执本身不作为完成依据。

取消回执的归属：重连或更换摘要任务后，旧取消的成功、失败与收尾都不会覆盖当前任务或提前解锁当前的「正在取消…」；新任务不会继承旧任务的取消等待。收到取消受理回执后，界面仍等待摘要终态，不把受理显示为已经取消。任务终态已经确认时，迟到的取消失败不会再提示「回执未知」；回执任务编号不符时提示核对。断连后先恢复连接并核对任务状态，再按需显式取消，不会自动重发。
内核明确表示摘要任务已不存在（进程重启或任务记录淘汰）时，界面收敛无法再终结的本地运行状态并说明任务不会重放；其他失败仍按回执未知处理。熟悉的摘要任务缺少开始应答、已知终态的详情无法读取时，界面会清除未确认的开始状态、停止跟踪并解除「正在生成摘要」锁，可重新生成计划；运行中任务连续无法核对时也会释放本地界面锁，但内核仍是任务与并发的权威，新请求仍可能被内核拒绝。

切换途中发生断连或重新连接时，旧操作的界面等待状态会解除。若切换尚未提交，旧队列核对回执不会在新连接上继续提交；若切换可能已经生效，旧成功回执也不会关闭重新打开的窗口或覆盖新操作状态。恢复连接后重新打开「会话分支」核对当前位置，再按需确认；不会回滚已生效的切换，也不会自动重试。

被放弃分支摘要未能生效时，「会话分支」窗口会显示未生效的总条数，并列出前 5 条的条目标识与原因；总数超过 5 条时注明「仅列出前 5 条」，不超过 5 条时列表完整且不另作提示。这些摘要不会进入模型上下文；被放弃分支的原始记录仍保留在本机，但不会注入当前分支，可在切换分支时重新生成摘要。

有招聘任务运行时退出应用会先确认。「继续运行」取消本次退出；「停止并退出」会中断运行中的回合。确认退出不表示已经撤销平台侧可能执行的操作；结果未知时仍需先核对。

## 继续中断回合

回合因停止、进程退出或运行中出错而没有正常结束时，侧栏状态与聊天区会把它标成「此回合已中断」，并显示「继续中断回合」入口（内核声明 `explicitTurnContinuation` 时；归档会话与本机内核之外的项目不显示）。显示与否按当前分支的末回合判断：切离被中断的回合后入口消失，切回后再出现。

显示提示的同时，桌面自动调用 `turn/continuation/read` 做一次只读预检，不发送请求。预检核对来源是否仍是当前分支的最新回合、当前分支上是否已有续接回合、是否还有未决审批或结果未知 / 未完成的工具调用、工具批次与请求边界是否完整持久化、已确认历史前缀与模型线路配置在中断后是否变化，以及来源回合是否已用完模型请求上限。检查点只会落在「用户输入」（`user_input`）或「已完成的工具批次」（`completed_tool_batch`）之前：前者从你那次输入重新请求，后者沿用已经确认的工具结果。

续接会发起一次新的模型请求，可能重复调用并产生额外费用；已确认完成的工具不会再次执行，新的写操作仍按原有规则逐次审批，回复写在新的续接回合里。来源回合使用的模型、技能、附件、工具策略与自动压缩策略会一并沿用。中断后改过会话模型线路、修改过已确认历史，或内核以显式 `none` 启动时，预检会拒绝续接。

续接判定按当前分支进行：续接回合所在分支被放弃、又切回来源回合后，来源重新成为当前分支的最新中断回合，可以再次续接，这会再发起一次模型请求。同一个续接编号在整份会话记录里不能重复使用：相同来源与编号重复提交按幂等返回已有回合，编号重复但来源不同会得到 `CONTINUATION_ID_CONFLICT`。切回旧回合再次续接与幂等重放是两件事，不要靠重试同一编号来重新执行。

预检不通过时，界面显示内核给出的原因与原因码，不会自动重试；完整原因码表见[技术参考](TECHNICAL_REFERENCE.md#中断回合续接)。按提示处理后重新打开入口，例如等待运行结束、清空投递中的队列、先处理未决审批或恢复归档会话。续接请求发出后没有拿到回执时，界面显示「等待核对续接结果」并禁用按钮，不会自动重发；先刷新会话状态，核对该回合是否已经启动，再决定下一步。

分叉会话遇到 `CONTINUATION_HISTORY_CHANGED` 时先核对来源：rc.422 之前创建的分叉会话，其继承的续接边界摘要按源会话的原始记录计算，与分叉复制后的记录不一致，预检会把这种情况报成历史变化；rc.422 起新建的分叉会按复制后的记录重算。若确认没有改过已确认历史，从源会话重新分叉后再续接，或在分叉会话里直接新建回合；不要靠重试同一续接编号绕过该检查。

## 项目分组

侧栏按项目分组时，可以从侧栏顶部菜单、项目区标题栏的「新建项目」或首页的项目菜单创建一个本机项目分组。名称按 Unicode 码点最多 60 个字符；超出上限时输入框下方显示「项目名称最多 60 字符」，并禁用「创建项目」。名称首尾空白会被去掉，只有空白的名称不能提交。

项目菜单的「更改项目显示名称」只修改本机显示，同样受 60 个码点上限约束，超出时提示并禁用「保存」；内核项目的标识与会话归属不变。项目菜单的「移除本地分组」只删除本机分组与聊天到该分组的映射，其中的聊天回到内核项目或默认分组，不会删除会话、草稿、附件或反馈记录。内核项目不能在本机移除，只能改名或折叠。

项目分组、显示名称与聊天归属保存在本机界面偏好中，不写入内核会话文件，也不同步到其他设备；沿用同一边界时，清除本机界面数据会一并丢失这些分组。侧栏显示选项可在「按项目」与「所有聊天」之间切换分组方式，排序、最近聊天与归档显示是独立的偏好。

## 跨会话搜索

在聊天列表或会话内按 `⌘K`（Windows / Linux 为 `Ctrl+K`）打开搜索窗口：会话标题与项目名从第 1 个字符起就参与过滤，输入至少 2 个字符后还会同时检索消息内容。搜索词按 Unicode 码点计数，最多 200 个字符；超过时消息内容不参与检索，只按标题与项目过滤，消息分区说明「未搜索消息」。消息内容匹配用户输入、模型正文与工具调用（工具名、来源编号、有界参数与结果摘要）。查询时间等本地化显示、思考内容以及按需读取的大结果正文不参与检索。搜索与高亮共用 Unicode 字素组合和规范化规则，重音顺序不同、兼容字符与新版组合记号在两端取得同一命中区间。结果按会话更新时间从新到旧排列，点击消息命中会打开对应会话、滚动到该消息并高亮关键词；工具命中还会展开工具块。归档会话默认不参与搜索，可在消息分区勾选「含已归档」纳入（内核声明对应能力时）。

搜索在本地直接读取会话记录，不调用模型或招聘平台，并且是有界的：最多扫描 100 个会话，返回最多 50 条消息、每个会话最多 5 条，另受文本扫描预算与单会话文件大小限制。超出这些上限、会话文件过大或会话无法读取时，消息分区会标注「仅显示部分结果」；没有其他消息命中时显示「消息搜索不完整」，不会断言「没有匹配的消息」。搜索结果状态行会同步给出结论：有命中且被截断时报「仅显示部分结果」，零命中且被截断时报「消息搜索不完整」。标注不完整只说明可能仍有未返回的命中，不代表会话已修复：日志损坏的会话不会因搜索而恢复，打开该会话时仍会看到读取错误；换更具体的关键词或稍后重试只会影响其余会话的命中。

## 归档与删除会话

侧栏会话菜单可归档或恢复聊天，标题栏与侧栏均提供「删除聊天」；归档后聊天移入侧栏「已归档」分组，需先恢复才能继续对话、切换分支、修改模型或推理档位。归档会暂停尚未完成的后续队列，恢复后不会自动投递，需要重新排队或撤回；未决审批同时失效。已投递的消息与已经执行的操作不会撤销。跨会话搜索默认不含已归档内容，可在消息分区勾选「含已归档」纳入。

「删除聊天」会从本机永久移除该会话及其全部消息，无法恢复。确认框会在存在时列出同时清除的未发送正文、附件、已选技能、正在读取的附件与消息反馈；只保存在本机的置顶、隐藏、别名、分组与返回历史也会一并移除。仍有运行中的回合、摘要、队列交接或清理任务时，内核以 `THREAD_BUSY` 拒绝，需先停止回合并清空队列；删除被拒时的提示会说明当前是哪一项占用，按提示处理后重试。删除覆盖会话记录、该会话的事件、索引与未被其他会话引用的附件；历史分支是独立副本，会继续保留。已经发给模型、客户端或 hook 的数据、外部工具创建的文件与招聘平台操作不会被撤销，也不承诺覆盖磁盘历史块或清理 Time Machine、文件系统快照与用户自行复制的备份。

删除结果未确认时，桌面保留会话列表并提示刷新核对，不把未确认当成已删除。`THREAD_DELETE_INCOMPLETE` 表示会话已隐藏、本机清理会在内核重启后继续；`THREAD_NOT_FOUND` 表示会话已不存在。两者都会从列表移除并给出对应提示。确认移除后的聊天不会因较早发出的列表刷新而重新出现；新建、重命名、归档 / 恢复及模型设置期间，较早的列表结果会被丢弃并补读最新列表。列表读取失败时保留已有内容并显示原因。

## 数据管理

设置 → 数据管理集中管理本机界面偏好和会话索引检查。

每次打开设置都是一轮新的操作：页脚回到默认说明「界面偏好仅保存在当前设备」，不保留上一轮的「界面偏好已保存」、导出或通知测试结果，「关于」页尚未完成的诊断信息复制回执也随之作废。

「导出界面偏好」把字体大小、紧凑会话、动态效果、审批提示音与主题写为 JSON；文件只包含 `boss-harness.ui.*` 白名单键，不包含聊天内容、候选人资料或模型凭据。「选择 JSON 文件」导入后会立即应用并写入本机存储；导入只接受 `version: 1` 与 `boss-harness.ui` 作用域（旧版 `boss-cli.ui` 文件仍可读取），字体大小限 12–16 px，任一已知键非法、文件为空或按 UTF-8 编码超过 64 KiB 时整体拒绝且不改动现有偏好，未知键忽略。没有主题键的旧导出文件仍可导入其余字段。本机存储不可用（隐私模式、配额用尽）时，弹窗会说明只应用到当前窗口，重启后不会保留。

「会话索引」检查无法解析、已被跳过索引的会话文件。只有内核明确报告 0 个坏文件时才显示「正常」；旧内核不返回这项检查结果时显示「未报告」，这时不能据此判断索引健康；读取失败显示「读取失败」。存在坏文件时显示完整数量，并列出前 5 个会话 id；原始日志不会被修改或删除，其余会话不受影响。退出应用后可运行 `boss-harness --repair-state`，在备份索引后从原始日志重建；该命令不改写日志内容，也不能恢复已被删除或篡改的原始记录。修复只针对已有的状态目录：`--state-dir` 或 `BOSS_HARNESS_DIR` 指向的路径不存在时，命令不创建任何文件，以退出码 2 结束并提示核对路径；相对路径按当前工作目录解析。路径存在但目录非空且不含任何内核状态文件（占用锁、`sessions`、`state.sqlite3`）时同样拒绝，避免路径少写一级时往其他目录写入；空目录与索引文件已丢失的状态目录仍可修复。

追加和重建索引时，会跳过缺少类型、正文或状态非法的队列记录，使会话列表待处理数与队列列表使用同一口径。既有日志未变化时不会强制重建缓存索引；如果历史会话两处计数仍不一致，可在退出应用后使用上述修复命令。索引检查显示「正常」只说明没有无法解析的会话文件，不代表每项历史派生计数都已重算。

## 工作区常驻说明

工作区存在 `.boss-harness/CONTEXT.md`（旧 `.boss-cli/CONTEXT.md` 仍兼容读取）时，内核在每个回合组装系统提示时读取一次，用于城市、薪资、硬性技能等长期偏好。文件须为不超过 8 KiB 的普通 UTF-8 文件，拒绝符号链接；内容只是上下文，不授予或扩大工具权限，也不改变审批要求与只读限制。编辑后下一回合生效，不需要重启；首选目录存在但文件不可读或超限时，状态会如实标注并忽略内容，不会静默回落到旧目录。

会话上下文面板显示该文件是否已加载、为空或已忽略；内核声明 `workspaceInstructionsEdit` 时可直接查看并保存，保存固定写入首选路径，旧位置仍生效时保存后旧文件不再被读取。「技能与工具」页提供同一入口，不用先打开会话。交互细节见[桌面交互指南](DESKTOP_GUIDE.md#技能与工作区说明)。

## 消息的后续模型上下文

已结束回合中的用户消息与助手文本可通过消息菜单「编辑后续模型上下文」查看原文、提交替换文本或排除该消息。替换内容最多 32000 字符且 UTF-8 不超过 128 KiB；编辑只改变后续模型输入，原始记录与已经执行的工具仍保留。活动消息、归档会话、工具条目与已纳入摘要的消息不能编辑。

编辑读取与成功回执按编码后的完整结果限制为约 1 MiB，包含原始文本与当前文本两部分。超过预算时显示 `RESPONSE_TOO_LARGE`，本次编辑不会写入；不应反复提交。可按错误中的快照分页提示核对原文；若长消息使编辑回执无法返回，可从该消息之前的完整回合创建分支，或在新会话中提供必要内容。分页读取原文不会解除编辑回执预算。

内核明确拒绝编辑（预算超限、来源已变化、会话归档或正在运行等）时，对话框说明「内核未受理、没有写入」并保留错误码；这与回执超时或连接中断不同，后者仍须重新读取权威状态再决定下一步，不能据此认定提交已经生效。来源变化后请核对当前内容再重新提交，不会自动重试。

## 自动压缩默认策略

内核默认启用自动压缩：输入预算使用达到 80% 时生成摘要，并尽量保留最近 20000 token。这里的「token」是预算估算口径，不是供应商 tokenizer 的精确计数：有同一业务线路的可信 `model_usage` 前缀时按 usage 增量校准各回合，否则按消息长度保守估算；切点只落在完整回合边界，且不会摘要当前运行回合。没有新增可压缩内容时计划会被拒绝，不会生成空摘要。桌面「设置 → 上下文」可查看并修改这三项默认值；内核侧对应 `config/autoCompaction/set`（能力 `autoCompactionConfig`），只接受 `enabled`、`triggerPercent`（1–100）与 `keepRecentTokens`（1–1000000）。保存后立即在当前进程生效，并原子写入内核状态目录下的 `config.json`；重启后仍生效，其他顶层配置键保持不变。摘要使用的 provider、model、effort 不在此界面修改，仍由启动配置决定。保留目标不低于当前模型输入预算时，自动压缩通常没有更早的可压缩内容，压缩后也可能仍超出预算；上下文面板会在设置与手动规划处提示，此时应调低保留目标或新建会话。「设置 → 上下文」在保留目标不低于当前模型上下文窗口时也会提示，默认值保存后对其他会话同样生效；内核断连或重新读取期间不显示该提示，避免把上一轮的窗口当成当前模型。

摘要可以使用与业务回合不同的 provider 或模型。若单独选择 Anthropic 且缺少非空环境凭据，桌面「会话上下文」会标明当前没有可用的摘要模型；仍可查看预算和整理计划，不能开始压缩。自动压缩与上下文溢出恢复均在提交前，按业务回合实际使用的 provider/model 检查摘要、保留历史、当前输入及工具定义的完整预算。容纳不下时以 `COMPACTION_INSUFFICIENT` 暂停，不保存新摘要检查点、不继续业务请求，原始记录与既有检查点保留；可减少当前输入或保留目标，或新建会话后明确继续。摘要线路本身不可用时，例如配置为 `none`、进程以显式 `none` 启动、本机缺少对应凭据或摘要模型不支持指定推理档位，当前回合也会以明确压缩错误码暂停，而不是笼统报成回合执行失败；先修正摘要配置或显式关闭自动压缩，再核对会话并明确发起下一步。暂停不自动重试或继续业务请求，也不撤销已执行的工具或外部操作。

策略来源经 `config/read` 的 `autoCompactionSource` 如实返回：`environment` 表示由 `BOSS_HARNESS_COMPACTION` 管理，`stored` 表示来自 `config.json`，`default` 表示内置默认，`explicit` 表示调用方在构造内核时显式指定。环境变量为空或只有空白时按未设置处理，不报告为 `environment`。环境变量优先于持久配置；此时设置页只读，直接调用 `config/autoCompaction/set` 会以 `AUTO_COMPACTION_ENV_MANAGED` 拒绝，不会静默覆盖环境变量；显式构造的内核以 `AUTO_COMPACTION_EXPLICIT` 拒绝写入。配置文件缺失或字段非法时按内置默认读取；文件存在但不可读或不是 JSON 对象时，保存会明确失败而不是覆盖原文件。单回合覆盖的语义不变：它优先于默认值，发送一次后消耗，不写入会话或 `config.json`。

## 快速提问

按 `⌘;`（Windows / Linux 为 `Ctrl+;`）或选择侧栏「快速提问」打开浮窗。已连接内核时，提问会经内核新建一个会话并立即发送，当前会话与正在运行的任务不受影响；成功后切换到新会话查看回复。等待期间未编辑输入时，浮窗关闭并清空已提交内容；有过编辑时（包括编辑后改回原文），当前输入与浮窗保持不变，提示原问题已提交到哪个会话，便于继续准备下一个问题。

输入法组合期间，Esc 交给输入法处理，不关闭浮窗，也不作废等待中的提交回执；普通 Esc 或关闭按钮可关闭浮窗，重新打开仍保留输入。组合态 Enter 不提交，结束组合后可正常发送。

创建或发送失败时输入保留并显示真实原因，不会自动重试，也不会在本地生成任何回复。模型线路按「当前会话 → 进程默认线路 → 目录中同一 provider 的条目」解析；解析不出精确线路或线路为 `none` 时明确拒绝，不拿显示值或目录首项猜线路。创建中禁止重复提交，内核未连接时禁用输入。浏览器预览模式（没有桌面桥）保留演示交互，回复全部标注为示例。

## 运行状态

按 `⌘⇧K` 或选择侧栏「运行状态」打开只读面板。每次打开会并行读取当前进程的配置、运行资源、待审批、工具与模型目录；存在当前会话时还会读取该会话的待处理队列。面板打开且内核已连接时，会随回合开始/结束、审批请求/裁决、队列变化与摘要任务开始/结束自动刷新；连续事件做防抖合并。面板不跨会话合并数据，切换会话后重新打开即按新会话读取。

队列摘要优先使用内核提供的持久待处理总数与持久分类计数，与队列面板、侧栏徽标一致；旧内核缺省分类、或分类合计与待处理总数不一致时，才按已载入项统计，截断投影下会标注「分类按可见项计数」。旧内核未提供总数时会明确标注「可见待处理」，截断投影合入本地队列项后仍保留这一口径。运行时长按整秒展示，例如 `120.4` 秒显示「2 分」、`121.9` 秒显示「2 分 1 秒」；该文字不参与超时判断。

概览展示 Provider、模型、进程级模型禁用标志（显式 `none` 启动时为「已由进程禁用」，旧内核不返回时为「未提供」）、协议、上下文窗口与输出上限、并发与保留回合、运行或收尾中的 owner、容量等待、审批与工具/模型数量以及自动压缩策略；审批策略、转向投递、能力来源与任务状态、阶段均以中文显示，内核新增的未知取值原样放在「」里。「回合」列出 owner 与等待者明细，「审批」列出待审批调用与到期提示，「工具与模型」列出 allowlist 属性与本机模型线路。回合 owner 可手动核对 `task/read` 持久记录：展示持久状态、归属、当前进程持有情况、恢复策略、任务阶段与已验证关联；尝试次数说明是否会自动重启，任务不在记录中时明确提示。核对只读，不恢复、不重放、不取消任务，失败不自动重试，关闭面板或切换会话后清除上次结果；后台会话的通知刷新不会清空已核对的结果。单个来源读取失败只影响对应分区并显示真实原因，其余分区继续展示；内核断连时清空数据并提示未连接。

队列任务核对遇到缺失或非法的持久状态时时保留「未知」状态并要求人工核对，不会把它当作已结束或可自动恢复。其他有效字段仍可读取；未知状态不证明消息未投递，也不能据此直接重发。

面板打开期间，审批到期提示每 15 秒按本机时间重算；「已运行 / 已等待」在上次资源快照的数值上叠加收到快照后的本机经过时间。新快照到达后重新起算，关闭后停止计时，不为更新时间文案增加内核读取。时间继续前进只说明经过了多久，不能单凭它判断任务仍在推进或已经卡住。

当前版本不接入 MCP，也不提供成本、缓存命中率、沙箱或死循环指标；面板不会用示例值填充未知字段。模型条目的 `available` 仅表示本机线路配置可用，不代表网络连通性或招聘平台验证。 会话用量遇到损坏的模型来源或回合编号时，仍展示可验证的合法记录；无法编码的来源字符会按会话读取的同一规则降级，过长编号会被跳过，不会让单条坏记录遮住整份用量。

## 上游 CLI 设置

上游 CLI 由独立仓库维护：[can4hou6joeng4/boss-agent-cli](https://github.com/can4hou6joeng4/boss-agent-cli)。其 README「快速开始」给出安装与诊断入口，例如 `uv tool install boss-agent-cli`；安装后先运行 `boss doctor` 核对平台与浏览器内核，再按下列顺序确认本 Harness 能找到它。登录、平台认证与网络边界由上游负责；本项目只查找可执行文件，并把上游状态目录与 Harness 会话目录分开。

业务可执行文件依次从 `BOSS_CLI_BIN`（去除首尾空白，空值或仅含空白时视为未设置）、并排的 `boss-agent-cli/.venv/bin/boss`、PATH 查找；仅为目录、断链或不可执行的候选会被跳过；指向可执行文件的符号链接仍可使用。显式设置 `BOSS_CLI_BIN` 却因不可执行被跳过、回退到其他来源时，自检报 `BOSS_CLI_BIN_IGNORED` 警告，不输出实际路径；最终没有可用 CLI 时仍报 `BOSS_CLI_UNAVAILABLE`。`BOSS_CLI_DATA_DIR` 管理上游登录和平台状态，取值会去除首尾空白，空值或仅含空白时视为未设置，工具桥与自检使用同一个规范化后的路径；`BOSS_HARNESS_DIR` 管理本项目会话（旧 `BOSS_CLI_HARNESS_DIR` 仍兼容），两者应分别配置。

可在启动 Harness 或桌面应用前设置 `BOSS_HARNESS_BROWSER_SOURCE` 为 `auto`、`existing-browser` 或 `stored-cookie`；取值会去除首尾空白并忽略字母大小写。未设置、空值或仅含空白时继承上游配置；显式设置需要上游支持 `--browser-source`，不支持时会明确失败，不会静默重试。取值无效时内核在启动阶段直接失败，错误会点名变量并列出可选值，不会带着错误配置继续运行。该选项不会读取或改写共享上游配置，也不替代单独的请求和认证边界检查。

## 明确条件搜索

在模型会话中可以要求“上海 Python、20–50K、3–5 年、本科，先看第一页”，模型通过 `boss_search` 传递结构化条件：

```json
{"keyword":"Python","city":"上海","salary":"20-50K","experience":"3-5年","education":"本科","page":1}
```

随后查看第二页时保持全部条件，只把 `page` 改为 `2`。工具不会自动拉取下一页，也不会自动放宽条件或逐个补取详情。平台返回 `has_more=null` 或没有分页信息时，是否还有后续结果仍未知；本页数量不能当作全量总数。

城市及岗位标签受当前适配契约的枚举约束，可通过 `tool/list` 查看。未知城市、标签、额外字段或非正整数页码在执行前被拒绝；旧 CLI 不支持新选项时保留明确错误，不去掉条件重查。平台标签与上游本地预筛不构成严格资格证明：经验、学历或薪资字段未知时须注明未知，再结合职位原始要求分析。

经验、学历也接受非空、无重复的枚举数组，例如“3–5 年或 5–10 年，本科或硕士”：

```json
{"keyword":"Python","city":"上海","experience":["3-5年","5-10年"],"education":["本科","硕士"],"page":1}
```

数组表示同一维度的任一标签，两个维度同时提交到一次指定页查询；不拆成组合搜索。传给业务 CLI 时按固定枚举顺序生成单个逗号参数，原始数组留在会话记录中。空数组、重复/未知标签、混合类型及逗号字符串均拒绝；省略字段才表示不设条件。下一页重复全部条件，仅改页码。城市、薪资仍只接受单标签。

多标签依赖平台筛选；当前业务上游对逗号经验/学历不执行单标签顺序粗筛。离线验证只能证明参数传递，不能证明平台严格返回集合内结果；须核对返回字段并标注未知或不匹配项。一次调用至多查询指定逻辑列表页，不补详情；缓存命中可能不发列表请求，因此工具来源上的查询时间只表示该次工具调用的事实快照，不保证每次调用都访问平台。网络尝试、认证及缓存维护仍由业务 CLI 决定，不能按工具调用次数推算网络请求量。

仅传 `keyword` 的旧调用继续有效，由上游默认读取第 1 页。无模型模式的 `/search 关键词` 仍为关键词查询快捷入口，不解析结构化筛选标志；不带关键词（或只输入空白）时只返回补全提示，不会以默认关键词发起检索。URL、薪资多选及更多列表筛选是后续扩展范围。

## 求职者沟通列表

配置模型后，可要求“查看求职沟通的第 1 页”或明确查询下一页。模型工具 `boss_chat` 只接受可选正整数 `page`，默认 1；一次提交指定逻辑页，不补取消息、不回复、不导出，也不自动翻页。无模型模式尚无求职者沟通列表的快捷命令；现有 `/chat` 调用的是招聘者沟通工具 `boss_hr_chat`，不是此处的求职者工具 `boss_chat`。

例如工具参数 `{"page":2}` 读取第 2 页；读取列表不改变角色、凭据或浏览器来源，当前业务上下文仍由用户配置决定，不能视为账号身份核验。列表标识、文本和上游建议命令不增加工具权限。

固定业务版本返回 `pagination=null`，表示后续页未知；空列表和条数不能证明查询结束。上游可能把缺失/null/真实零未读数都输出为 `unread=0`，把缺失最近消息输出为 `last_msg="-"`；这些值不能证明已读或没有消息。`initiated_by` 是关系发起方，非最近发言方；`msg_status` 也不是已核实的阅读状态，不能据此判断“待我回复”。工具保留来源值，不补造已丢失的事实。

请求、认证及本地状态维护沿用业务 CLI，无法保证单次网络访问或首次限制即停；收到最终受支持停止码后暂停当前回合，不执行同批后续工具或自动模型续跑。恢复会话只读取历史，不自动重查；处理限制后由用户明确发起后续任务。
