## 模型配置来源

OpenAI Responses 的完整显式配置由以下三项组成，去除首尾空白后均须非空：

| 配置 | 来源 |
| --- | --- |
| 端点 | `BOSS_HARNESS_OPENAI_BASE_URL` |
| 凭据 | `BOSS_HARNESS_OPENAI_API_KEY` |
| 模型 | 命令行 `--model`，其次为 `BOSS_HARNESS_MODEL`、`BOSS_HARNESS_OPENAI_MODEL` |

三项齐备时不访问 Codex 配置文件，Python 3.10 也可使用这一路线；可选推理强度只取 `BOSS_HARNESS_EFFORT`，未指定则由模型服务决定，不再继承文件中的值。`BOSS_HARNESS_MODEL` 覆盖进程默认 provider 的模型；`BOSS_HARNESS_OPENAI_MODEL` 可为 OpenAI 线路提供模型，Anthropic 线路对应 `BOSS_HARNESS_ANTHROPIC_MODEL`。

Anthropic 线路另有两个可选项。`BOSS_HARNESS_SERVER_FALLBACK` 控制请求是否携带服务端回退参数（走对应的 beta 接口）：未设置时，`ANTHROPIC_BASE_URL` 未设置或指向官方主机则开启，指向其他网关则关闭；显式取值去除首尾空白并按不区分大小写解析，`1` / `true` / `yes` / `on` 为开启，`0` / `false` / `no` / `off` 与空值为关闭，其他取值以 `MODEL_SERVER_FALLBACK_INVALID` 明确失败，不会被当作开启。网关不支持该参数时应保持关闭。`BOSS_HARNESS_THINKING=summarized` 请求模型返回思考摘要，其他取值或未设置时不请求。这两项只作用于 Anthropic 线路，`none` 与 OpenAI 线路不因它们失败。

选择 `none` 时（显式 `--provider none`、`BOSS_HARNESS_PROVIDER=none` 或没有可用凭据时自动回退），内核不读取模型名与推理档位：握手、`config/read`、`model/list` 与新建会话统一使用 `none · none`，设置 `BOSS_HARNESS_MODEL` 或 `BOSS_HARNESS_EFFORT` 不会改变该线路，也不会发起模型请求。`none` 仍可调用招聘 CLI 与上游只读工具。

缺少任一项时才读取 `BOSS_HARNESS_CODEX_CONFIG`、`CODEX_HOME/config.toml` 或默认 `~/.codex/config.toml`，按此顺序选择文件，显式字段仍优先。读取 TOML 需要 Python 3.11+；已有文件不可读或语法损坏时明确报错，不退到其他 provider。文件不存在或缺少可用 profile 时继续检查端点与凭据，缺项会报错；未提供模型且没有可用文件模型时保留既有 `DEFAULT_MODEL`。

当前文件适配要求文件自身同时提供 `model`、`model_provider` 及该 provider 的 `base_url` 才形成可用 profile；凭据支持 provider 的 `experimental_bearer_token`，或由 `env_key` 指定环境变量名并从该变量读取；显式 `BOSS_HARNESS_OPENAI_API_KEY` 优先于文件凭据，文件内 `experimental_bearer_token` 优先于 `env_key`。OpenAI 线路仅支持 Responses：profile 的 `wire_api` 缺省或为空白时使用 `responses`，显式值忽略首尾空白并按不区分大小写处理；其他值或非字符串会以 `MODEL_CODEX_WIRE_API_UNSUPPORTED` 拒绝，不自动改用其他协议。应选择支持 Responses 的端点，不能仅修改标识来适配只支持 Chat Completions 的服务。尚未适配 Codex 的 OAuth。配置解析只读本地文件，不探测真实服务。

## 本地配置自检

此入口已进入 `v0.2.0-rc.18` 候选，尚未发布。可以在命令行运行 `.venv/bin/boss-harness --check`，也可以在桌面内核启动失败后由主进程自动运行；两种方式使用同一套检查。与正常启动一样，可传入 `--provider` 与 `--model`，沿用上文的配置优先级。只核对不使用模型时，可显式传入 `--provider none`。CLI 自动模式在未设置 provider 且没有 Anthropic 凭据时会回退为 `none` 并给出警告；核对桌面默认的 OpenAI 线路时，请显式使用 `--check --provider openai`。

命令向 stdout 输出单份 JSON 报告，`schemaVersion` 为 `1`，`ok` 表示未发现本地配置错误；`checks` 逐项提供固定检查码、`ok` / `warning` / `error` 状态、说明及处理建议。存在 `error` 时退出码为 `2`，全部通过或仅有警告时为 `0`。

| 检查项 | 固定检查码 | 检查范围与限制 |
| --- | --- | --- |
| 模型配置 | `MODEL_CONFIG_VALID` / `MODEL_DISABLED` / `MODEL_NOT_CONFIGURED` / `MODEL_CONFIG_INVALID` / `MODEL_CONFIG_INCOMPLETE`，以及下表的具体错误码 | 只复用本地解析，不构造 SDK 或发起请求；缺少必需配置、文件损坏或非正输出上限记为错误，显式 `none` 与自动回退分别记为禁用模型、未配置模型警告。 |
| 业务 CLI | `BOSS_CLI_FOUND` / `BOSS_CLI_UNAVAILABLE` | 只发现可执行文件，不执行 `boss schema`、版本查询、登录或任何工具；未发现可执行文件记为警告，文件存在不证明 CLI 能正常运行。 |
| 浏览器来源 | `BROWSER_SOURCE_VALID` / `BROWSER_SOURCE_INVALID` | 只校验 `BOSS_HARNESS_BROWSER_SOURCE` 的取值，不读取浏览器或 Cookie，也不验证上游是否支持该选项。 |
| 状态目录 | `STATE_DIRECTORY_VALID` 及下文的目录错误码 | 只读核对实际状态路径的目录类型、所有权、父目录与 ACL 安全规则，以及基本访问条件；缺失路径只核对已有父目录，不创建或试写。 |
| 运行参数 | `RUNTIME_OPTIONS_VALID` 及下文的运行参数错误码 | 复用正常启动的解析，校验转向模式、模型请求上限、附件存储上限、模型容量与自动压缩环境变量的格式和取值；不读取状态目录中的持久设置。 |

运行参数检查（rc.18 候选内容，尚未发布）覆盖取值无效时会让内核启动失败的环境变量，按启动时的读取顺序报告遇到的第一个错误，修复后应再次运行：

| 固定检查码 | 环境变量与处理 |
| --- | --- |
| `STEERING_MODE_INVALID` | `BOSS_HARNESS_STEERING_MODE` 只能是 `all` 或 `one-at-a-time`；也可取消设置。 |
| `MAX_MODEL_REQUESTS_INVALID` | `BOSS_HARNESS_MAX_MODEL_REQUESTS` 须为 1 到 64 的十进制整数。 |
| `ATTACHMENT_STORAGE_LIMIT_INVALID` | `BOSS_HARNESS_MAX_ATTACHMENT_STORAGE_BYTES` 与 `BOSS_HARNESS_MAX_ATTACHMENT_STORAGE_OBJECTS` 须为正的十进制整数。 |
| `MODEL_LIMITS_INVALID` | `BOSS_HARNESS_MODEL_LIMITS` 的 JSON 结构、`provider/model` 键或容量取值无效；格式见[内核与业务契约参考](TECHNICAL_REFERENCE.md)。 |
| `COMPACTION_CONFIG_INVALID` | `BOSS_HARNESS_COMPACTION` 的 JSON 字段、类型或取值范围无效；格式见[内核与业务契约参考](TECHNICAL_REFERENCE.md)。 |

报告不回显这些变量的原值。检查只判断格式与取值范围，不核对摘要线路的凭据、声明的容量是否与模型服务一致，也不读取 `config.json` 中的持久自动压缩设置。

模型配置错误进一步提供以下固定码（rc.18 候选内容，尚未发布）；命令行与桌面显示同样的说明和建议：

| 固定检查码 | 含义与处理 |
| --- | --- |
| `MODEL_ENDPOINT_MISSING` | OpenAI 线路缺少端点；设置 `BOSS_HARNESS_OPENAI_BASE_URL`，或在有效 Codex profile 的 provider 中配置 `base_url`。 |
| `MODEL_CREDENTIAL_MISSING` | OpenAI 线路缺少凭据；设置 `BOSS_HARNESS_OPENAI_API_KEY`，或在有效 Codex profile 的 provider 中配置 `experimental_bearer_token` 或 `env_key` 指向的环境变量。 |
| `MODEL_CODEX_UNREADABLE` | 无法读取 Codex 配置文件；核对配置路径与读取权限。 |
| `MODEL_CODEX_INVALID_TOML` | Codex 配置的 TOML 格式无效；检查语法与文件编码。 |
| `MODEL_CODEX_NOT_FILE` | Codex 配置路径不是普通文件；将 `BOSS_HARNESS_CODEX_CONFIG` 指向文件，或核对 `CODEX_HOME` 下的 `config.toml`。 |
| `MODEL_CODEX_WIRE_API_UNSUPPORTED` | Codex profile 声明了内核不支持的协议或值类型；选择支持 Responses 的端点并将 `wire_api` 设为 `responses`，或使用完整显式 OpenAI 配置跳过该文件。 |
| `MODEL_PROVIDER_UNKNOWN` | `BOSS_HARNESS_PROVIDER` 的取值无法识别；设为 `none`、`anthropic`、`openai` 或 `codex`，或取消设置以自动选择。 |
| `MODEL_MAX_TOKENS_INVALID` | `BOSS_HARNESS_MAX_TOKENS` 不是正整数；设为正整数，或取消设置以使用默认值。 |
| `MODEL_REQUEST_TIMEOUT_INVALID` | `BOSS_HARNESS_MODEL_REQUEST_TIMEOUT_SECONDS` 不是 1 到 3600 的整数；修正取值，或取消设置以使用默认值。 |
| `MODEL_SERVER_FALLBACK_INVALID` | Anthropic 线路的 `BOSS_HARNESS_SERVER_FALLBACK` 不是可识别的开关写法；设为 `1` / `true` / `yes` / `on` 或 `0` / `false` / `no` / `off`，或取消设置以按端点取默认值。 |

一次自检只报告解析时遇到的第一个模型配置错误，修复后应再次运行；业务 CLI、浏览器来源与状态目录仍独立检查。配置来源与覆盖顺序不变：完整显式模型、端点和凭据会跳过 Codex 文件；需要补全时，损坏或不可读的已有文件以及可用 profile 中不支持的 `wire_api` 会明确失败，文件缺失则继续核对必需字段。正常启动对已登记的模型配置错误在 stderr 输出同一固定码与静态说明，退出码为 `2`。供应商拼写、输出上限、请求期限与服务端回退开关错误使用上表的专用码；其余未细分的错误继续返回 `MODEL_CONFIG_INVALID`；Anthropic 缺少必需字段仍为 `MODEL_CONFIG_INCOMPLETE`。报告结构与 `schemaVersion: 1` 不变，按检查码处理的调用方应保留未知码的通用错误展示。

状态目录检查同属 rc.18 候选内容，尚未发布，使用正常启动实际选择的路径：`--state-dir` 优先于 `BOSS_HARNESS_DIR`，其次为旧变量 `BOSS_CLI_HARNESS_DIR`；均未设置时，新默认目录不存在而旧默认目录存在才沿用旧目录。相对路径按启动工作目录解析，环境变量中的 `~` 不额外展开，符号链接沿用正常启动的真实路径解析方式。

| 目录错误码 | 含义与处理 |
| --- | --- |
| `STATE_DIRECTORY_NOT_DIRECTORY` | 状态路径或父级被文件等非目录对象占用；保留已有文件，核对配置并选择独立目录。 |
| `STATE_DIRECTORY_ACCESS_DENIED` | 已有状态目录缺少读取、写入或进入权限，或缺失路径的已有父目录不可写、不可进入；核对权限后重新连接。 |
| `STATE_DIRECTORY_INVALID` | 路径或目录安全条件不符合内核规则，例如根目录、非当前用户拥有的目标目录、允许他人修改的目录或 ACL，以及路径无法解析（如符号链接环）；选择可信的独立目录，不要放宽权限。 |
| `STATE_DIRECTORY_UNSUPPORTED` | 当前系统或解释器缺少内核私有状态机制要求的文件或 ACL 能力。 |
| `STATE_DIRECTORY_UNAVAILABLE` | 其他文件系统错误导致无法完成核对；检查路径、文件系统与权限。 |

已有目录沿用正常启动的安全规则，不要求统一改成某一权限值；自检也不会自动收紧权限。目录缺失时只核对已有父目录，后续目录由正常启动创建。路径无法解析（如符号链接环）同属无效路径：自检报 `STATE_DIRECTORY_INVALID`，正常启动与 `--repair-state` 都以固定中文说明和退出码 2 结束，不打印 Python 回溯或本机绝对路径。检查不获取占用锁、不打开索引或会话、不尝试真实写入；通过不证明磁盘空间充足、路径没有被另一内核占用或索引与会话完整，实际启动仍是最终核对。

从命令行直接启动内核而在构造阶段失败时（状态目录不可用、系统不满足私有状态目录要求、运行参数取值无效等），stderr 在失败行之后会追加一行固定提示，建议用相同参数与环境运行 `boss-harness --check`；该提示在 rc.18 候选之后合入主干，尚未发布。

报告不包含端点、密钥、模型自定义值、本机路径、会话内容或异常原文，可用于报告安装问题。自检不创建状态目录、不修改权限、不读取会话、不写入索引，与 `--repair-state` 互斥。本地检查仅覆盖上表五项，不核对模型 SDK 是否已安装，也不核对审批期限、重试次数等取值无效时回退默认值的参数。通过不代表模型可连接、认证有效、平台已登录或真实工具已验收；这些操作应分别在获得授权后核对。

## 桌面启动失败时的自检

本地内核未能完成启动时，桌面会自动运行一次上述自检，每个失败周期一次。本次连接在握手完成前失败才运行，包括曾经就绪后重新启动失败；自动重试期间沿用同一结论，就绪或点「重新连接」后作废，恢复连接后提示自动清除。

- 自检使用与内核相同的解释器、工作目录与环境（只额外设置输出编码），因此结论与内核实际使用的配置一致；它不调用模型、不执行业务 CLI、不访问招聘平台。
- 错误项的说明与建议显示在底部提示条，以及「设置 → 模型与连接」的「招聘 Harness」行；后者按「错误 → 警告 → 通过」列出明细与检查码，同类项保留自检报告的原始顺序，方便先找到导致启动失败的原因。该展示顺序在 rc.18 候选之后合入主干，尚未发布；命令行报告顺序不变。
- 提示条区分「内核未能完成启动」与「就绪后断开」：前者说明自动重试是否仍会继续；后者保留「结果未确认的对外操作请先核对平台状态」，自动恢复重新就绪后清除。
- 界面不展示内核 stderr、异常原文、端点、凭据或本机路径，只使用上表的固定检查码与静态建议。
- 自检未发现配置错误时仍可能启动失败，说明问题在已返回检查项的范围之外（例如依赖未装好、实际写入失败、磁盘空间不足或目录已被另一内核占用），请按提示逐项排查。
- 结论只用于排查，不替代重新连接。修正配置文件或目录条件后可重新连接；解释器与相关环境变量在应用启动时确定，更换解释器或修改这些变量后需重启应用。

## 单次模型请求期限

OpenAI Responses 与 Anthropic Messages 的单次传输默认最多运行 600 秒，可用 `BOSS_HARNESS_MODEL_REQUEST_TIMEOUT_SECONDS` 设置为 1–3600 的整数秒。该 wall-clock 总时限覆盖连接建立和流式响应；SDK 原有的 30 秒连接/读取空闲时限仍然生效，周期性 SSE 心跳不会延长总时限。

超时不会标记为用户取消，也不进入上下文溢出恢复。后台清理在期限内确认完成时，它作为可重试传输错误结束；若清理仍未完成，内核停止自动重试并保留该传输的资源额度。OpenAI 仅在尚无可见输出且清理已确认时遵循既有重试策略，每次 attempt 各自重新计时；Anthropic 不新增自动重试。这不是跨重试或 Agent 自动恢复的共享总预算。

每个内核进程最多保留 8 个模型传输，业务回合、摘要与连接检查共同使用；未完成后台清理的传输也占用额度，满额时新请求在发出前失败。流事件队列最多保留 64 项、估算共 4 MiB，单事件最多 2 MiB。该预算针对 SDK 已解码对象，不能限制 SDK 解码单帧时的临时内存或整个进程 RSS。

## 其他运行参数

以下环境变量在内核启动时读取一次，修改后需重启内核（桌面需重启应用）。桌面启动的内核继承应用进程的环境变量。

| 变量 | 作用 | 默认值与范围 | 取值无效时 |
| --- | --- | --- | --- |
| `BOSS_HARNESS_MAX_TOKENS` | 单次模型请求的输出上限，同时作为上下文预算中的输出预留。 | 64000；正整数。 | 启动失败，自检报 `MODEL_MAX_TOKENS_INVALID`。 |
| `BOSS_HARNESS_MAX_MODEL_REQUESTS` | 单个回合最多发起的模型请求数；回合自带的上限只能在此基础上收紧。 | 6；1–64 的十进制整数。 | 启动失败，自检报 `MAX_MODEL_REQUESTS_INVALID`。 |
| `BOSS_HARNESS_RETRY_ATTEMPTS` | 模型请求在首个输出前遇到可重试失败时的最多尝试次数，含首次；设为 `1` 即不自动重试。 | 3；1–10。 | 不是整数时使用默认值；超出范围时收敛到 1 或 10。 |
| `BOSS_HARNESS_RETRY_BASE_MS` | 自动重试的退避基数（毫秒），每次重试翻倍。 | 500；非负整数。 | 不是整数时使用默认值；负数按 0 处理。 |
| `BOSS_HARNESS_APPROVAL_TIMEOUT` | 需审批的工具调用等待裁决的期限（秒），到期后该审批按过期处理，不执行调用。 | 300；正数，可带小数。 | 不是数字、非有限值或不大于 0 时使用默认值。 |
| `BOSS_HARNESS_PYTHON` | 桌面应用启动内核与运行自检所用的 Python 解释器，需为 3.10 及以上并已安装内核。 | 仓库根目录的 `.venv/bin/python`，不存在则为 `python3`。 | 解释器无法启动时桌面提示未能启动 Python 解释器。 |

自动重试的单次等待最长 8 秒；模型服务返回建议等待时间时以其为准，同样不超过 8 秒。重试只发生在向会话产出首个内容之前，并受回合内共享的模型恢复预算约束，与[单次模型请求期限](#单次模型请求期限)相互独立。实际生效的审批期限可在握手结果的 `approval.timeoutSeconds` 中核对。

表中标为「使用默认值」或「收敛」的三项不会让启动失败，也不在[本地配置自检](#本地配置自检)的范围内：配置看似未生效时，请先核对取值是否符合上表。转向模式、附件存储上限、模型容量与自动压缩等其余变量见 README 的配置表与自检检查码表。

## 技能与队列

把运行时技能放在工作区 `.boss-harness/skills/<id>/SKILL.md`（旧 `.boss-cli/skills` 仍兼容读取），可用 frontmatter 的 `name` 与 `description` 提供菜单名称和说明。在输入区选择技能后，它会随一次直接发送或「排到后续回合」的队列消息进入该回合的提示上下文；技能不会执行目录脚本，也不会扩大工具清单或审批范围。目录最多发现 100 个普通技能文件，每个文件最多 64 KiB；每次最多选择 10 项。转向当前回合的消息不使用技能，已选技能时会提示清除或改为后续回合。

任务运行时，可将新消息转向当前回合，或排到当前回合结束后；停止任务是独立操作。队列状态会持久化，尚未投递的项目可以撤回。启动失败且确认输入尚未写入会话的后续回合项可直接「重新排队」：沿用原输入与技能创建新队列消息，并撤回旧项；其余失败、结果不确定或结算异常时，队列会暂停并要求先核对；不会自动重放工具、审批或招聘平台操作。相同 `clientUserMessageId` 会关联原请求，输入已接受不表示回合已成功。仍在排队的消息可在投递前经 `queue/update` 编辑正文：只接受 `queued` 项，保留技能、自动压缩覆盖与请求编号，正文仍限 1–100000 字符并受待处理队列字节上限约束；桌面编辑截断项时会先读取完整正文。会话读取与 `queue/list` 只返回待处理项及最近 50 个已终结项（单次最多 200 项），正文预览最多 600 字符并标注截断；重新排队经 `queue/get` 读取该项完整正文与技能，不会复用预览。

## 暂停队列批量处理

队列里有至少两条可重试的暂停消息时，可选择「重新排队全部暂停项」；有至少两条暂停消息时，也可选择「撤回全部暂停项」，核对数量和预览后再确认。批量入口只处理暂停项，排队中与投递中的消息仍按单条操作。

批量操作按列表顺序逐条执行，进度显示已处理数量。处理中可点「停止剩余」：当前这一条完成后不再开始下一条，已成功的操作不回滚，其余暂停消息保留；遇到明确拒绝或结果未确认也会停止。切换会话会停止发起后续请求，已完成的结果仍属于原会话。

单条撤回需确认，撤回后正文不会自动恢复。结果未确认时先核对队列状态；不要将它当成明确未受理并直接重复提交。批量期间单条操作和刷新入口会暂时禁用，避免对同一批条目交叉修改。

## 会话与阅读状态

应用启动后会恢复上次打开且仍在列表中的会话；如果记录已删除或不再列出，则停留首页。回到首页的新建任务入口会结束这次自动恢复目标。恢复会话只读取历史，不会自动发起模型或招聘平台操作。

本次应用运行期间，切回会话会恢复已缓存的消息与队列、滚动位置、工具 / 思考块展开状态和聊天内查找。切到后台失败的会话时仍能查看该会话的失败原因；关闭提示后不再重复显示。输入区正文与技能另按草稿规则写入本机存储；阅读位置等内存状态不代表重启后全部恢复。

最近聊天页与 `⌘K` 搜索窗口保持打开时，每 15 秒按本机时间更新相对时间；异步消息命中到达时保留已选中的结果。关闭或离开后停止本地计时，不额外读取内核。

有招聘任务运行时退出应用会先确认。「继续运行」取消本次退出；「停止并退出」会中断运行中的回合。确认退出不表示已经撤销平台侧可能执行的操作；结果未知时仍需先核对。

## 归档与删除会话

侧栏会话菜单可归档或恢复聊天，标题栏与侧栏均提供「删除聊天」；归档后聊天移入侧栏「已归档」分组，需先恢复才能继续对话、切换分支、修改模型或推理档位。归档会暂停尚未完成的后续队列，恢复后不会自动投递，需要重新排队或撤回；未决审批同时失效。已投递的消息与已经执行的操作不会撤销。跨会话搜索默认不含已归档内容，可在消息分区勾选「含已归档」纳入。

「删除聊天」会从本机永久移除该会话及其全部消息，无法恢复。确认框会在存在时列出同时清除的未发送正文、附件、已选技能、正在读取的附件与消息反馈；只保存在本机的置顶、隐藏、别名、分组与返回历史也会一并移除。仍有运行中的回合、摘要、队列交接或清理任务时，内核以 `THREAD_BUSY` 拒绝，需先停止回合并清空队列。删除覆盖会话记录、该会话的事件、索引与未被其他会话引用的附件；历史分支是独立副本，会继续保留。已经发给模型、客户端或 hook 的数据、外部工具创建的文件与招聘平台操作不会被撤销，也不承诺覆盖磁盘历史块或清理 Time Machine、文件系统快照与用户自行复制的备份。

删除结果未确认时，桌面保留会话列表并提示刷新核对，不把未确认当成已删除。`THREAD_DELETE_INCOMPLETE` 表示会话已隐藏、本机清理会在内核重启后继续；`THREAD_NOT_FOUND` 表示会话已不存在。两者都会从列表移除并给出对应提示。确认移除后的聊天不会因较早发出的列表刷新而重新出现；新建、重命名、归档 / 恢复及模型设置期间，较早的列表结果会被丢弃并补读最新列表。列表读取失败时保留已有内容并显示原因。

## 自动压缩默认策略

内核默认启用自动压缩：输入预算使用达到 80% 时生成摘要，并尽量保留最近 20000 token。桌面「设置 → 上下文」可查看并修改这三项默认值；内核侧对应 `config/autoCompaction/set`（能力 `autoCompactionConfig`），只接受 `enabled`、`triggerPercent`（1–100）与 `keepRecentTokens`（1–1000000）。保存后立即在当前进程生效，并原子写入内核状态目录下的 `config.json`；重启后仍生效，其他顶层配置键保持不变。摘要使用的 provider、model、effort 不在此界面修改，仍由启动配置决定。

摘要可以使用与业务回合不同的 provider 或模型。自动压缩与上下文溢出恢复均在提交前，按业务回合实际使用的 provider/model 检查摘要、保留历史、当前输入及工具定义的完整预算。容纳不下时以 `COMPACTION_INSUFFICIENT` 暂停，不保存新摘要检查点、不继续业务请求，原始记录与既有检查点保留；可减少当前输入或保留目标，或新建会话后明确继续。

策略来源经 `config/read` 的 `autoCompactionSource` 如实返回：`environment` 表示由 `BOSS_HARNESS_COMPACTION` 管理，`stored` 表示来自 `config.json`，`default` 表示内置默认，`explicit` 表示调用方在构造内核时显式指定。环境变量优先于持久配置；此时设置页只读，直接调用 `config/autoCompaction/set` 会以 `AUTO_COMPACTION_ENV_MANAGED` 拒绝，不会静默覆盖环境变量；显式构造的内核以 `AUTO_COMPACTION_EXPLICIT` 拒绝写入。配置文件缺失或字段非法时按内置默认读取；文件存在但不可读或不是 JSON 对象时，保存会明确失败而不是覆盖原文件。单回合覆盖的语义不变：它优先于默认值，发送一次后消耗，不写入会话或 `config.json`。

## 快速提问

按 `⌘;`（Windows / Linux 为 `Ctrl+;`）或选择侧栏「快速提问」打开浮窗。已连接内核时，提问会经内核新建一个会话并立即发送，当前会话与正在运行的任务不受影响；成功后浮窗关闭并切换到新会话查看回复。

创建或发送失败时输入保留并显示真实原因，不会自动重试，也不会在本地生成任何回复。模型线路按「当前会话 → 进程默认线路 → 目录中同一 provider 的条目」解析；解析不出精确线路或线路为 `none` 时明确拒绝，不拿显示值或目录首项猜线路。创建中禁止重复提交，内核未连接时禁用输入。浏览器预览模式（没有桌面桥）保留演示交互，回复全部标注为示例。

## 运行状态

按 `⌘⇧K` 或选择侧栏「运行状态」打开只读面板。每次打开会并行读取当前进程的配置、运行资源、待审批、工具与模型目录；存在当前会话时还会读取该会话的待处理队列。面板打开且内核已连接时，会随回合开始/结束、审批请求/裁决、队列变化与摘要任务开始/结束自动刷新；连续事件做防抖合并。面板不跨会话合并数据，切换会话后重新打开即按新会话读取。

概览展示 Provider、模型、协议、上下文窗口与输出上限、并发与保留回合、运行或收尾中的 owner、容量等待、审批与工具/模型数量以及自动压缩策略；「回合」列出 owner 与等待者明细，「审批」列出待审批调用与到期提示，「工具与模型」列出 allowlist 属性与本机模型线路。回合 owner 可手动核对 `task/read` 持久记录：展示持久状态、归属、当前进程持有情况、恢复策略、任务阶段与已验证关联；任务不在记录中时明确提示。核对只读，不恢复、不重放、不取消任务，失败不自动重试，关闭面板或切换会话后清除上次结果。单个来源读取失败只影响对应分区并显示真实原因，其余分区继续展示；内核断连时清空数据并提示未连接。

面板打开期间，审批到期提示每 15 秒按本机时间重算；「已运行 / 已等待」在上次资源快照的数值上叠加收到快照后的本机经过时间。新快照到达后重新起算，关闭后停止计时，不为更新时间文案增加内核读取。时间继续前进只说明经过了多久，不能单凭它判断任务仍在推进或已经卡住。

当前版本不接入 MCP，也不提供成本、缓存命中率、沙箱或死循环指标；面板不会用示例值填充未知字段。模型条目的 `available` 仅表示本机线路配置可用，不代表网络连通性或招聘平台验证。

## 上游 CLI 设置

业务可执行文件依次从 `BOSS_CLI_BIN`、并排的 `boss-agent-cli/.venv/bin/boss`、PATH 查找。`BOSS_CLI_DATA_DIR` 管理上游登录和平台状态；`BOSS_HARNESS_DIR` 管理本项目会话（旧 `BOSS_CLI_HARNESS_DIR` 仍兼容），两者应分别配置。

可在启动 Harness 或桌面应用前设置 `BOSS_HARNESS_BROWSER_SOURCE` 为 `auto`、`existing-browser` 或 `stored-cookie`。未设置时继承上游配置；显式设置需要上游支持 `--browser-source`，不支持时会明确失败，不会静默重试。取值无效时内核在启动阶段直接失败，错误会点名变量并列出可选值，不会带着错误配置继续运行。该选项不会读取或改写共享上游配置，也不替代单独的请求和认证边界检查。

## 明确条件搜索

在模型会话中可以要求“上海 Python、20–50K、3–5 年、本科，先看第一页”，模型通过 `boss_search` 传递结构化条件：

```json
{"keyword":"Python","city":"上海","salary":"20-50K","experience":"3-5年","education":"本科","page":1}
```

随后查看第二页时保持全部条件，只把 `page` 改为 `2`。工具不会自动拉取下一页，也不会自动放宽条件或逐个补取详情。平台返回 `has_more=null` 或没有分页信息时，是否还有后续结果仍未知；本页数量不能当作全量总数。

城市及岗位标签受当前适配契约的枚举约束，可通过 `tool/list` 查看。未知城市、标签、额外字段或非正整数页码在执行前被拒绝；旧 CLI 不支持新选项时保留明确错误，不去掉条件重查。平台标签与上游本地预筛不构成严格资格证明：经验、学历或薪资字段未知时须注明未知，再结合职位原始要求分析。

经验、学历也接受非空、无重复的枚举数组，例如“3–5 年或 5–10 年，本科或硕士”：

```json
{"keyword":"Python","city":"上海","experience":["3-5年","5-10年"],"education":["本科","硕士"],"page":1}
```

数组表示同一维度的任一标签，两个维度同时提交到一次指定页查询；不拆成组合搜索。传给业务 CLI 时按固定枚举顺序生成单个逗号参数，原始数组留在会话记录中。空数组、重复/未知标签、混合类型及逗号字符串均拒绝；省略字段才表示不设条件。下一页重复全部条件，仅改页码。城市、薪资仍只接受单标签。

多标签依赖平台筛选；当前业务上游对逗号经验/学历不执行单标签顺序粗筛。离线验证只能证明参数传递，不能证明平台严格返回集合内结果；须核对返回字段并标注未知或不匹配项。一次调用至多查询指定逻辑列表页，不补详情；缓存命中可能不发列表请求。网络尝试、认证及缓存维护仍由业务 CLI 决定，不能按工具调用次数推算网络请求量。

仅传 `keyword` 的旧调用继续有效，由上游默认读取第 1 页。无模型模式的 `/search 关键词` 仍为关键词查询快捷入口，不解析结构化筛选标志。URL、薪资多选及更多列表筛选是后续扩展范围。

## 求职者沟通列表

配置模型后，可要求“查看求职沟通的第 1 页”或明确查询下一页。模型工具 `boss_chat` 只接受可选正整数 `page`，默认 1；一次提交指定逻辑页，不补取消息、不回复、不导出，也不自动翻页。无模型模式尚无求职者沟通列表的快捷命令；现有 `/chat` 调用的是招聘者沟通工具 `boss_hr_chat`，不是此处的求职者工具 `boss_chat`。

例如工具参数 `{"page":2}` 读取第 2 页；读取列表不改变角色、凭据或浏览器来源，当前业务上下文仍由用户配置决定，不能视为账号身份核验。列表标识、文本和上游建议命令不增加工具权限。

固定业务版本返回 `pagination=null`，表示后续页未知；空列表和条数不能证明查询结束。上游可能把缺失/null/真实零未读数都输出为 `unread=0`，把缺失最近消息输出为 `last_msg="-"`；这些值不能证明已读或没有消息。`initiated_by` 是关系发起方，非最近发言方；`msg_status` 也不是已核实的阅读状态，不能据此判断“待我回复”。工具保留来源值，不补造已丢失的事实。

请求、认证及本地状态维护沿用业务 CLI，无法保证单次网络访问或首次限制即停；收到最终受支持停止码后暂停当前回合，不执行同批后续工具或自动模型续跑。恢复会话只读取历史，不自动重查；处理限制后由用户明确发起后续任务。
